# AIWorkGate 插件格式规范

> 本文是**规范**（主机实际执行什么），《插件开发指南》是**教程**（怎么做一个）。
> 两边冲突时以本文为准，并以代码为最终依据。核查日期 2026-10-23，对应宿主 v0.1.0。
>
> 强制点都在代码里，`go test ./internal/plugins` 的 `TestRepositoryManifestsAreValid` 会用
> 安装器同一套校验跑一遍 `plugins/*/manifest.json`——**规范不是靠自觉，是靠这条门禁**。
>
> 怎么从源码产出一个合规的 zip，见 [`插件生成契约.md`](插件生成契约.md)（打包器 + 签名 + 安装门禁）。

## 1. 目录与文件布局

安装根：`%APPDATA%\AIWorkGate\plugins\<id>\`（数据目录可被 `APPDATA` 重定向）。

| 文件 | 必需 | 说明 |
|---|---|---|
| `manifest.json` | **是** | 描述文件。文件名固定；`plugin.json` 不被识别。≤ 1 MiB |
| `entry.exe` 指向的文件 | **是** | 相对路径、普通文件；复制到安装目录后再校验一次 |
| `manifest.sig` | 否 | 包签名。配置了 `plugins.trusted_keys` 时变为**必需**，见 §11 |
| 其余文件/子目录 | 否 | DLL、资源、静态文件。复制时**拒绝符号链接与特殊文件** |

宿主生成、插件只读：

| 路径 | 内容 |
|---|---|
| `%APPDATA%\AIWorkGate\plugin-data\<id>\` | 插件自己的持久化目录（环境变量 `AIWORKGATE_PLUGIN_DATA_DIR`） |
| `%APPDATA%\AIWorkGate\runtime\<id>\rules.json` | 规则包（环境变量 `AIWORKGATE_RULES_FILE`） |
| `%APPDATA%\AIWorkGate\runtime\<id>\egress.json` | 出口分配（环境变量 `AIWORKGATE_EGRESS_FILE`） |
| `%APPDATA%\AIWorkGate\logs\plugins\<id>-YYYY-MM-DD.log` | 插件的 stdout/stderr 原样落盘 |
| `secrets.dat`（DPAPI） | 插件 token。**没有 token 文件**，只有环境变量 |

**zip 安装**：`manifest.json` 必须在根或唯一顶层目录；忽略 `__MACOSX` 与点目录；禁路径穿越、禁符号链接、解压总量 ≤ 1 GiB。更新流程是 Stop → 解到 staging → 目录改名替换，**`plugin-data` 与用户设置保留**；zip 新装默认**不启用**。

**发现**：每次扫描 `plugins/*`。某个 manifest 坏了，只把该插件标成 `failed` 并记录 `last_error`，不中断其它插件。

## 2. manifest.json 字段

未知键被**静默忽略**（标准 `json.Unmarshal`）——写错字段名不会报错，只会不生效。宿主发现插件时会为未知的顶层键与已知块内的未知字段写一条告警（`plugin manifest has unknown keys; they are ignored`），但不拒装。

### 2.1 顶层

| 字段 | 类型 | 必填 | 默认 | 规则 / 缺失后果 |
|---|---|---|---|---|
| `id` | string | **是** | — | `^[a-z0-9][a-z0-9-]{1,31}$`；决定安装目录名 |
| `name` | string | 否 | `""` | 仅展示 |
| `version` | string | 否 | `""` | **仅展示**。宿主不比较大小、不要求最低版本 |
| `api_level` | int | **是** | — | 只能 `1` 或 `2`；缺失（0）与 3 都会被拒 |
| `description` / `author` / `homepage` | string | 否 | `""` | 仅展示 |
| `os` | []string | 否 | 空=不限 | 非空时**必须包含 `windows`**（忽略大小写） |
| `capabilities` | []string | 否 | 空 | **无白名单校验**，未知值静默无效；见 §3 |

### 2.2 配置块

| 字段 | 类型 | 默认 | 规则 / 宿主行为 |
|---|---|---|---|
| `permissions.read_paths` | []string | 空 | **不读取、不校验、不沙箱** |
| `permissions.launch_apps` | []string | 空 | 同上 |
| `permissions.network_domains` | []string | 空 | 同上（纯文档） |
| `permissions.use_proxy` | bool | false | **不被消费**；是否走代理由 egress 决定 |
| `permissions.require_admin` | bool | false | 不被消费 |
| `permissions.os_identity` | bool | false | 与能力 `identity_os_switch` **同时存在**才允许 OS 级身份重置 |
| `models[]` | object[] | 空 | `id` 须匹配 `^[A-Za-z0-9._:-]+$`。非空时**取代** `GET /v1/models` 的返回，不再向插件要模型 |
| `checkin.default_time` | string | 空→宿主设置 | 非空须 `HH:MM`；**非法值直接安装失败**，不会回退 |
| `checkin.supports_history` | bool | false | 宿主当前不读 |
| `quota.poll_minutes` | int | 缺省=30 | `0` = 不定时轮询；负数拒绝 |
| `concurrency.suggested` | int | 0 = 跟随全局 | 0–32，越界拒绝 |
| `rules.packs` | []string | 空 | 未知包只告警，插件照常启动 |
| `egress.strict` | bool | false | 与全局 `plugins.strict_egress` 取**或**；插件设置里的 `StrictSet` 可覆盖 |
| `startup.mode` | string | 空→`always` | 只接受 `always` / `on_demand`；空值会被规范化成 `always`（**不跟随**全局 `plugins.startup_mode`） |
| `startup.idle_timeout_s` | int | 0→600 | 负数拒绝；只对 `on_demand` 有意义 |
| `entry.exe` | string | **必填** | 相对路径、不含 `:`、不含 `..` 越界、非目录；安装后必须存在 |
| `entry.args` | []string | 空 | 原样传给子进程 |
| `login` | object | nil | 存在即覆盖由能力推导出的登录策略；字段 `methods` / `reads_local_state` / `requires_app` / `auto_refresh` / `notes` |

## 3. 能力（capabilities）

词表：`upstream`、`accounts`、`checkin`、`quota`、`login_api_key`、`login_oauth`、`login_paste_code`、`login_ide_plugin`、`login_local_state`、`login_cookie`、`refresh`、`egress`、`identity_request`、`identity_os_switch`，外加 v0.4 的 `embeddings`、`images`。

匹配**区分大小写、忽略首尾空白**。**拼错不会拒绝加载**，但宿主在发现插件时会写一条告警
（`plugin declares unknown capabilities; they will never match`），因为这等于把功能悄悄关掉。

宿主真正据此改变行为的能力只有下面几个，其余目前只是展示/占位：

| 能力 | 宿主行为 |
|---|---|
| `checkin` | 没有就**不参加**定时签到与「一键全签」，签到页也不列该插件 |
| `quota` | 没有就跳过额度轮询 |
| `egress` | 出口分配变化后，只对**运行中**的这类插件发 `POST /reload` |
| `identity_os_switch` + `permissions.os_identity` | 缺一则 OS 级身份重置返回 400 |
| `login_*` | 推导登录方式列表；`login_local_state` 附带 `reads_local_state=true`，`refresh` 附带 `auto_refresh=true` |
| `upstream` / `accounts` / `identity_request` | **无门禁**：调度快照对每个已安装插件都会读 `/accounts` 和 `/v1/models` |
| `embeddings` / `images` | **当前无效果**：插件模型的 `/v1/embeddings`、`/v1/images` 一律 501 |

## 4. api_level 与版本

| 级别 | 含义 |
|---|---|
| `1` | 整池调度：宿主不指定账号 |
| `2` | 宿主可以指定账号转发（`X-Aiworkgate-Account` 头），调度器才会做固定/粘滞 |

- 宿主加载时校验 `1 ≤ api_level ≤ 2`，越界（含缺失、或未来值 3）→ 插件**不可启动**。
- 宿主把 manifest 的 `api_level` 原样注入 `AIWORKGATE_API_LEVEL`。
- `version` 字段**不参与任何判断**；宿主升级不检查插件版本，插件升级也不检查宿主版本。破坏性变更只能靠 `api_level` 表达。

## 5. 生命周期

1. **选端口**：宿主向系统要一个空闲端口后立刻释放，把端口号经环境变量下发。
2. **启动**：`cmd.Dir` = 插件目录，`cmd.Args` = `entry.args`；窗口隐藏。环境先删掉所有 `AIWORKGATE_*` 再注入（防继承）。
3. **证明端口归你**：5 秒内宿主用 `netstat -ano` + 父进程链确认监听者是自己拉起的子进程；不通过就**不下发 token**。监听 `127.0.0.1`、`0.0.0.0`、`::` 都接受。
4. **健康检查**：每 100 ms 打 `GET /health`，总预算 15 秒；要求 2xx，且 JSON 里 `ok != false`、`status`（若有）为 `ok`。
5. **运行期**：每 10 秒一次 `GET /health`，**连续 2 次**失败判死并重启（约 20 秒发现）。
6. **重启退避**：1s → 2s → 5s → 10s → 30s；10 分钟内 5 次失败标 `failed`，10 分钟后自动再试。
7. **停止**：先 `taskkill /T`（优雅）等 3 秒，再 `/F` + Kill 整棵进程树。
8. **空闲回收**：`startup.mode=on_demand` 时每 30 秒检查，空闲超过 `idle_timeout_s` 才停，**有在飞请求不收**。
9. **单实例**：同一插件同时只允许一个进程；安装/更新先 Stop。

## 6. RPC 协议

纯 HTTP，`127.0.0.1:<下发的端口>`，每个请求带 `Authorization: Bearer <AIWORKGATE_PLUGIN_TOKEN>`。响应最大 8 MiB。宿主不校验你的 token——**你必须校验**。

| 方法与路径 | 请求体 | 响应 | 超时 |
|---|---|---|---|
| `GET /health` | — | 2xx | 2s |
| `GET /meta` | — | 插件自述（含能力、版本）；插件页「自述」按钮触发 | 5s |
| `GET /accounts` | — | `{"accounts":[…]}` | 60s |
| `PATCH /accounts/{id}` | 任意 JSON（如 `{"enabled":false}`） | 无体 | 60s |
| `DELETE /accounts/{id}` | — | 无体 | 60s |
| `POST /accounts/{id}/checkin` | `{}` | 签到结果 | **5 min** |
| `POST /accounts/{id}/refresh` | `{}` | 刷新结果 | 60s |
| `POST /accounts/login` | `{"method":…}` | 登录开始结果 | 60s |
| `POST /accounts/login/{sid}/submit` | `{"values":{…}}` | 登录状态 | 60s |
| `GET /accounts/login/{sid}` | — | 登录状态 | 60s |
| `DELETE /accounts/login/{sid}` | — | 404/405 视为成功 | 60s |
| `POST /accounts/{id}/identity/reset` | `{"mode":"request"\|"os"}` | 无体 | 20s |
| `GET /v1/models[?refresh=1]` | — | `{"data":[…]} / {"models":[…]} / […]` 均可 | 60s |
| `POST /reload` | `{}` | 404/501 视为成功 | 60s |
| `POST /admin/upstream` | `{"base_url","api_key"}` | 无体 | 60s |
| `POST /v1/chat/completions` | 网关转发的 chat 请求 | 流式原样透传 | 90s 头超时 |

网关转发时：body 里的 `model` 会被改写成插件侧模型名，附加 `X-Aiworkgate-Request-Id`、`X-Aiworkgate-Hedge`，`api_level=2` 时还有 `X-Aiworkgate-Account`；客户端带来的 `Authorization` / `X-API-Key` / `X-Client-Key` **会被剥离**，插件只认宿主 token。

**错误约定**：非 2xx 即失败。宿主优先取 `error.message`，其次正文前 256 字节，再其次状态文本。

## 8. 文件通道

### `egress.json`

```json
{
  "version": 1,
  "strict": false,
  "default": { "mode": "direct|proxy|blocked", "url": "http://<token>@127.0.0.1:<port>", "proxy_id": "…" },
  "accounts": { "<account-id>": { "mode": "…", "url": "…", "proxy_id": "…" } }
}
```

- 宿主在插件**启动前**整体重写，变更后对声明 `egress` 的运行插件发 `/reload`。
- `url` 指向宿主在本机开的 CONNECT 转发器，**不含上游代理账密**；userinfo 是每监听器随机令牌，插件只需把它当 HTTP 代理用（`http.ProxyURL` 会自动带 `Proxy-Authorization`），缺失或错误一律 407。
- `strict=true` 时 `direct` 一律变 `blocked`；代理不可用时，strict → `blocked`，非 strict → 回退 `direct`。
- 未单独分配的账号继承 `default`。

### `rules.json`

```json
{ "packs": ["…"], "rules": [{ "from": "…", "to": "…" }], "strip": [{ "pattern": "…" }] }
```

原子替换；没有规则时也写空文档。

## 9. 宿主强制 / 不强制

**强制**（做不到就装不上或起不来）：

1. `manifest.json` 存在、≤1 MiB、`id` / `api_level` / `entry.exe` 合法。
2. zip 无符号链接、无路径穿越、≤1 GiB。
3. 配置了 `plugins.trusted_keys` 时，`manifest.sig` 必须存在且由受信 key 签名（§11）。
4. 必须监听下发端口，且监听者确实是你的进程——否则拿不到 token。
5. 15 秒内 `/health` 返回 2xx。
6. 单实例。

**不强制**（宿主不会替你检查，出问题在请求时才暴露）：

- **没有沙箱**：插件以当前用户权限运行，`permissions` 除 `os_identity` 外不被读取。
- 不检查你打印了什么——stdout/stderr 原样落盘，**token 就在环境变量里，别打印**。
- 不检查你校验了 token。
- 不检查你实现了 `/v1/chat/completions`、`/accounts`、`/v1/models`；缺失只会让调度/转发降级。
- 不检查 `version` 兼容性。

## 10. 给插件作者的版本策略建议（规范未强制）

宿主目前只认 `api_level` 这一个数字。在引入更细的兼容机制之前，建议自律：

1. **只增不改**：新增可选字段可以，改变已有字段语义必须升 `api_level`。
2. **未知字段要容忍**：宿主传下来的 JSON 可能比你知道的多，忽略而不是报错。
3. **`/health` 要便宜**：它每 10 秒被调一次，别在里面打上游。
4. **`/accounts` 要快**：调度快照会周期性拉它，慢账号会拖慢整池决策。
5. **凭据只进不出的**：账号凭据由插件自己保管（DPAPI / 系统凭据库），不要让宿主经手明文。

## 11. 包签名（可选，默认可关）

插件是原生进程，安装即执行。宿主本身不提供沙箱（§9），签名是唯一的**来源校验**：
它回答「这个包是不是我信任的 key 签的」，不回答「这个包会不会做坏事」。

### 格式

包根下的 `manifest.sig`：

```json
{
  "alg": "ed25519",
  "key_id": "dev",
  "manifest_sha256": "<manifest.json 的 sha256 十六进制>",
  "entry_sha256": "<入口 exe 的 sha256 十六进制>",
  "signature": "<base64(Ed25519 签名)>"
}
```

签名的字节串恰好是：

```
<key_id>\n<manifest_sha256>\n<entry_sha256>
```

因此改 manifest 或换 exe 都会失效。

### 启用

`config.json`：

```json
{
  "plugins": {
    "trusted_keys": { "dev": "<base64 32 字节 Ed25519 公钥>" }
  }
}
```

- **空/缺失**：不校验，未签名的包照常安装（仓库自带的 12 个插件就是这种状态）。
- **非空**：每个包都必须带 `manifest.sig`，且 `key_id` 在表里、摘要匹配、签名有效；否则安装失败。
- 启动时校验配置：公钥不是 32 字节 base64 会让宿主拒绝启动，而不是静默忽略。

### 生成

```powershell
go run ./tools/plugin-sign -gen -key dev.key -key-id dev
# 输出一行 "dev": "<公钥>"，粘到 plugins.trusted_keys

powershell -ExecutionPolicy Bypass -File scripts/pack-plugin.ps1 `
  -PluginDir .\my-plugin -SigningKey .\dev.key -KeyID dev
```

私钥是 32 字节种子的 base64 文本，**不要提交**（根 `.gitignore` 已忽略 `*.key`）。

### 边界

- 签名只保证包在签名后未被修改，不保证插件行为安全；安装后它仍以当前用户权限运行。
- 宿主不验证签名时间、过期或吊销：换 key 就更新 `trusted_keys`。
- 已安装的插件不会因 key 被移出 `trusted_keys` 而停止；校验只发生在安装/更新时。
