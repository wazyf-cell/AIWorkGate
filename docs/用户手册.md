# AIWorkGate 用户手册

> 面向第一次使用、不写代码的用户。文中"宿主"= AIWorkGate 本体（`aiworkgate.exe`），"A"= AI Work 助手。
> 本手册按当前版本（`0.1.0-dev`）的实际行为编写。个别功能页面还没做完，会明确标注「当前版本边界」，不会让你去找不存在的按钮。

---

## 1. 它是什么

AIWorkGate 是装在你电脑上的一个"本地网关"：

- 对外只暴露一个地址：`http://127.0.0.1:7865`（只允许本机访问）；
- 所有 AI 客户端只填这一个地址、一把 Key；
- 请求按模型名分流：裸模型名（如 `gpt-4o`）转给 A；`插件id/模型名`（如 `mock/mock-chat`）转给对应插件；已绑定的逻辑模型名（如 `kimi`）可在多个插件间自动调度；
- 插件是独立的小程序，可单独安装/更新/停用/卸载；
- 宿主附带一个网页面板，用来管插件、账号、签到、代理、日志。

它不会修改 A，也不会把 A 的 Key 或账号复制走。

## 2. 安装与第一次启动

### 2.1 运行

1. 把发布包解压到任意目录（例如 `D:\Tools\AIWorkGate\`）。
2. 双击 `aiworkgate.exe`。没有安装向导，也不需要管理员权限。
3. 首次启动会自动创建数据目录：

```
%APPDATA%\AIWorkGate\
```

（把 `%APPDATA%` 粘到资源管理器地址栏回车即可打开，通常是 `C:\Users\你的用户名\AppData\Roaming\AIWorkGate`。）

4. 右下角托盘会出现图标；浏览器会自动打开管理页：`http://127.0.0.1:7865`。

### 2.2 托盘菜单

右键托盘图标，只有四项：

| 菜单 | 作用 |
|---|---|
| 打开管理页 | 用默认浏览器打开面板 |
| 暂停全部插件 | 停掉所有正在运行的插件进程（文件和数据保留） |
| 恢复全部插件 | 重新启动"随宿主启动"的插件；按需插件保持停止，等请求再拉起 |
| 退出 | 正常关闭宿主（会停插件、关数据库） |

### 2.3 端口

- 默认 `7865`。
- 如果 7865 被占用，宿主会**自动**依次尝试 `7866 … 7875`，并把实际端口写进：

```
%APPDATA%\AIWorkGate\run\gateway.port
```

  这时管理页地址要换成实际端口，例如 `http://127.0.0.1:7866`。
- 如果 7865–7875 **全部**被占用，宿主启动失败并退出（从命令行运行 `aiworkgate.exe` 才能看到错误文字）。处理办法：在「设置」里改一个空闲端口，**保存后重启宿主**。端口修改不会即时生效。
- 端口也只影响管理页；OpenAI 客户端的 `base_url` 也要跟着改。

### 2.4 只允许开一个

宿主是单实例的。重复双击 `aiworkgate.exe` 不会启动第二个，只会把已经在运行的那个管理页打开。

### 2.5 开机自启

默认开启：宿主在注册表 `HKCU\...\Run` 写一条名为 `AIWorkGate` 的启动项，指向当前 exe 路径。
在「设置」里关掉后，这条启动项会被删除。**移动/重命名 exe 后请重新打开一次**，让自启路径更新。

### 2.6 局域网访问（可选）

「设置」里勾选"允许局域网访问"后：

- 必须先设置"局域网密码"，否则宿主仍只绑定 `127.0.0.1`（日志里会有一条警告）；
- 其他设备访问面板时浏览器会弹 Basic 认证，用户名随便填，密码就是局域网密码；
- 局域网设备请用 **IP 地址**访问（如 `http://192.168.1.10:7865`）。宿主只接受回环名称（localhost/127.0.0.1/::1）和 IP 字面量，带域名的主机名会被拒绝——这是为了防止 DNS rebinding 绕过管理接口的同源校验；
- `/v1` 接口不受这个密码影响，仍然必须带客户端 Key。

### 2.7 健康检查

宿主提供 `GET /health`（不在 `/v1` 下，也不需要客户端 Key）：

```
curl -s http://127.0.0.1:7865/health
{"status":"ok","running":true}
```

只要宿主进程还在监听，就返回 **200** 和上面这段 JSON，不检查插件、账号或 A 的状态；适合做启动器/看门狗的探活。它不需要客户端 Key，局域网模式下也不要求网页密码（只暴露「宿主活着」这一条信息）。`HEAD /health` 也接受（无响应体），其他方法返回 405。

另有 `GET /healthz`（同样免 Key、在管理鉴权之前处理，`HEAD` 也可用，其他方法 405，响应带 `Cache-Control: no-store`），它表示「有没有号可调度」，适合让看门狗区分「进程活着但没号」：

- 至少有一个可调度账号（启用、有凭据、未冷却、积分未耗尽、出口可用）：**200** `{"status":"ok","selectable":N,"total":M,"egress_failed":K}`；
- 可调度账号为 0，但被挡住的全是**代理出口失败**：**200** `{"status":"degraded","reason":"egress_failed",…}`——代理问题重启宿主修不好，所以不用 503 触发看门狗重启；
- 一个可调度账号都没有（且不是出口问题）：**503** `{"status":"unavailable","reason":"no_account"}`；
- 启动宽限期或调度器尚未就绪：**200** `{"status":"ok","reason":"scheduler_unavailable"}`。

`egress_failed` 统计「本来可调度、只因绑定的代理最近失败而不计入」的账号数；它和 `selectable` 相加不一定等于 `total`（冷却、禁用等原因之外的对账见调度页的判定说明）。响应里只有计数，不含账号 ID、凭据或其他敏感信息。

## 3. 接入 A（AI Work 助手）

### 3.1 填什么

打开「设置」→ A 区域：

| 项 | 说明 |
|---|---|
| 网关地址 | 默认 `http://127.0.0.1:7864`。宿主启动时会尝试从 A 的本地数据（`%APPDATA%\AIWorkAssistant`）里**只读**读取 A 自己记录的网关端口；读到就用读到的端口，读不到才用你填的地址。所以这里填错不一定立刻报错 |
| A 的 exe 路径 | 只用于"一键全签"调用 A 的命令行任务。留空时宿主会去注册表 `HKCU\...\Run` 里找名字像 `ai-work-assistant.exe` 的自启项 |
| 模型缓存（分钟） | 默认 10，范围 1–1440。A 的模型列表在这段时间内复用 |
| A Key | 粘贴一次，点"保存 Key"。宿主用 Windows DPAPI 加密后存进 `secrets.dat`，之后只显示"已保存"，不会回显 |

### 3.2 为什么 A 的 Key 必须手动粘贴

A 把 Key 存在它自己的 Stronghold 加密仓库里，宿主**无法**读取或导入。你需要在 A 里找到（或新建）一把 API Key，复制到宿主设置里粘贴一次。

### 3.3 A 没运行时会发生什么

- A 的裸模型请求返回 **502**，错误消息是"AI Work 助手未运行"；
- `GET /v1/models` 仍能返回 A 上次缓存的模型列表（响应头带 `X-AIWorkGate-A-Stale: 1`，网页不显示这个标记）；
- **宿主不会自动启动 A**。设置里的"自动启动 A"字段目前不会生效，网页上也没有"启动 A"按钮——请手动打开 A；
- 插件模型不受影响，照常可用。

## 4. 客户端 Key 与接入 OpenAI 客户端

### 4.1 Key 的规则

- 形如 `agk_` + 32 个随机字符；
- 宿主只保存它的 SHA-256 哈希（在 `secrets.dat` 里），**明文只在创建时显示一次**，丢了只能删掉重建；
- 可以创建多把、分别命名；默认权限相同，可另外限定**模型范围**、**绑定插件**、**每日配额**（见 4.4）；
- 删除 Key 后，用它的客户端立刻 401。

### 4.2 怎么创建

「设置」页的「客户端 Key」区块可以直接新建/删除（明文只在创建响应里出现一次）。

管理接口 `/api/*` 现在只接受**同源本机请求**（校验 `Origin`/`Referer`/`Sec-Fetch-Site`），并要求宿主下发的会话 Cookie：`curl`/PowerShell 直接打 `/api/keys` 会得到 403 `cross_origin` 或 `admin_session_required`。这是刻意收口——此前本机任意网页的 JS 都能替你造 Key、改设置、装插件（插件没有沙箱）。要在脚本里创建，就在已打开的管理页里用同源 `fetch`。

- 端口换成实际端口（见 `run\gateway.port`）；
- 只读请求会自动补发会话 Cookie，写请求必须先有一次同源读；宿主重启后 Cookie 会变，重新加载页面即可；
- 局域网模式下管理接口还要额外的网页密码（Basic）；
- 这一层挡的是「浏览器里的网页」和「局域网其他机器」，**不挡本机已运行的进程**（它能读内存/文件，也能直接连 127.0.0.1）。

### 4.3 在客户端里填

任何 OpenAI 兼容客户端（Cherry Studio、ChatBox、各类 SDK、IDE 插件）：

```
base_url = http://127.0.0.1:7865/v1
api_key  = agk_...（刚复制的那把）
```

注意 `base_url` **要带 `/v1`**。连接测试一般会请求 `GET /v1/models`。
鉴权头三种都认：`Authorization: Bearer`、`x-api-key`、`api-key`（后两个是给 Anthropic / Azure 风格 SDK 留的）。

Python 示例：

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:7865/v1", api_key="agk_...")
print(client.chat.completions.create(
    model="officeace/glm-5.2",
    messages=[{"role": "user", "content": "你好"}],
).choices[0].message.content)
```

`mock/mock-chat` 是随宿主附带的**假模型**，只用于自测连通性，别配进正式 agent。

### 4.4 Key 的作用域与配额

在「设置 → 客户端 Key」新建或点某行「编辑」可以设置：

| 字段 | 含义 | 留空的含义 |
|---|---|---|
| 模型范围 | 允许调用的模型，逐行或逗号分隔；支持 `officeace/glm-5.2` 精确名和 `officeace/*` 前缀 | 不限 |
| 绑定插件 | 裸模型名只路由到该插件（带别的插件前缀会 404） | 不绑 |
| 每日配额 | 每个自然日（宿主本地时区）允许的推理请求次数 | 0 = 不限 |

- 只统计真正到达模型的推理请求（chat / completions / responses / messages）；`/v1/models`、`/v1/embeddings`、越界被拒的请求都不计数；
- 模型名比较会忽略首尾空白与大小写：范围里写 `officeace/GLM-5.2`，请求 `officeace/glm-5.2` 也算命中（`GET /v1/models` 的合并列表同样按这个规则去重）；
- 每日配额在请求进入网关时就以一条条件更新**原子预占**一个名额：同一把 Key 并发打进来也不会超卖（第 N+1 个请求在 N 个名额用完时直接 429）。因模型范围/绑定插件被拒（404）的请求没有到达模型，预占的名额会退回；已通过准入后上游失败、或客户端中途断开（499）的请求都算一次；
- 超出范围的模型返回 **404** `model_not_found`，文案会指明是该 Key 的限制；配额用尽返回 **429** `key_quota_exceeded`，`Retry-After` 是到次日 00:00 的秒数；
- 列表里的「今日用量 / 配额」按宿主本地日期统计；`PUT /api/keys/{id}` 可改这些字段（管理接口同样要求同源会话）。

### 4.5 模型名怎么填

| 来源 | 模型名 | 例子 |
|---|---|---|
| 插件 | `插件id/插件内模型名` | `officeace/glm-5.2`、`codearts/GLM-5.2` |
| 逻辑名 | 「调度 → 模型绑定」里定义 | `kimi` |
| A | 裸名，和 A 里看到的一样 | `gpt-4o` |
| 自定义模型 | 「设置 → 自定义模型」里的「模型名称」（≤64 字符、不含 `/`、忽略大小写唯一） | `my-gpt-4o` |

- 模型列表以 `GET /v1/models` 为准：插件模型带前缀，逻辑名 `owned_by=scheduler`，A 的模型是裸名，自定义模型 `owned_by` 与 `vendor` 都是 `custom`；
- 插件内模型名里不允许 `/`，也不允许中文（显示名可以是中文）；
- 写错模型名：插件前缀存在但模型不存在 → **404** `model_not_found`，错误消息里会列出最多 20 个可用模型；在「资源」页被取消「接入」的模型同样 404；完全没见过的裸名会转给 A，由 A 决定。

### 4.6 支持哪些接口

| 客户端路径 | 插件模型 | A |
|---|---|---|
| `POST /v1/chat/completions` | 支持（含流式、tools） | 原样转发 |
| `POST /v1/completions` | 支持（内部转 chat 再回译，含流式） | 原样转发 |
| `POST /v1/responses` | 支持（转译 + Responses 事件流） | 原样转发 |
| `GET /v1/models` | 合并列表 | 合并列表（A 挂了用缓存） |
| `POST /v1/messages` | 支持（Anthropic 协议，转译 + `message_start…message_stop` 事件流） | 原样转发 |
| `/v1/embeddings`、`/v1/images/*` | 返回 **501** | 原样转发 |

插件模型走的是转译层，不支持 `echo/suffix/logit_bias/best_of/n>1` 与 Responses 的 `background`；`previous_response_id` 接受但忽略（网关无状态，每轮请带完整 `input`，只给指针不给内容会 400）。空输出算上游失败：流式会以 `empty_response` 报错而不是回一个空结果。

`/v1/responses` 返回的 `id` 以 `resp_` 开头（与上游 chat 的 `chatcmpl-` 不同），流式时 `response.created` 与 `response.completed` 用同一个 id；网关不保存该 id，`previous_response_id` 只做透传兼容。
完整端点说明、curl 示例、SSE 事件序列、错误码表见 **`docs/外部Agent接入.md`**。

### 4.7 自定义模型（OpenAI 兼容上游直连）

「设置 → 自定义模型」卡片位于「客户端 Key」之后、「插件」之前，用来把一个任意 OpenAI 兼容上游直接接进网关，不经过插件与调度。

字段与操作：

- 添加 / 编辑：模型名称、API 地址（`base_url`）、上游模型名、API Key；列表中可启停、看 Key 状态（「已配置 / 未配置」）、点「测试」、编辑、删除。
- 模型名称就是客户端请求里的 `model`，也是路由键：非空、最多 64 个字符、不能包含 `/`（该前缀保留给插件）；去首尾空白并忽略大小写后必须唯一，重名返回 **409**。
- API 地址必须是完整的 `http(s)://` 地址，不能带查询参数或片段；`http://` 只接受本机回环地址（localhost、127.0.0.1 等），远程地址必须用 `https://`。末尾带不带 `/v1` 都可以：带 `/v1` 时请求发往 `<base>/chat/completions`，不带时发往 `<base>/v1/chat/completions`。
- API Key 只保存在宿主本机的 DPAPI 加密存储里（extras 键 `custom_model.<id>.api_key`），不写数据库、不写 `config.json`；接口只返回 `key_set`，页面与会话都不回显 Key。新建时必须填 Key；编辑时不传该字段则保留原 Key，传空字符串才清除；删除模型会一并清除 Key。
- 「测试」是一个显式动作：用保存的 Key 向上游发一条 `ping`（`max_tokens=1`、非流式），超时 5 秒，返回 `latency_ms`。保存本身不会探测上游。失败返回 **502**，原因里的 Key 会被抹掉。

路由与边界：

- 支持四个对话类端点：`POST /v1/chat/completions`、`POST /v1/messages`、`POST /v1/responses`、`POST /v1/completions`（均含流式与非流式）。`chat/completions` 直达上游的 chat 端点；其余三个先用与插件模型相同的转译层把请求转成 chat，再把上游 chat 回复回译成对应协议。都用保存的 Key 做 Bearer 认证，客户端的 AIWorkGate Key 不会转发给上游；返回内容里的 `model` 会被改写回你填的模型名称（流式逐帧改写）。
- `/v1/embeddings`、`/v1/images*` 不走自定义模型，仍按普通路由处理（自定义条目对这些路径没有特殊支持）。
- `GET /v1/models` 列出启用的自定义模型；同名时插件模型或逻辑名优先，冲突条目在设置页标「与现有模型冲突」，且不出现在列表里、不参与路由。
- 用量与 Key 计数照常记录，请求日志（`api_logs`）与 `X-AIWorkGate-Source` 的来源是 `custom:<条目 id>`；Key 的「模型范围」照常生效；绑定了插件的 Key 不会走自定义模型。

## 5. 插件：安装、更新、卸载

### 5.1 安装（zip）

1. 打开「插件」页；
2. 选择本机的 zip 文件上传（**不支持填服务器路径**），点"上传并安装"；
3. 宿主解压 → 校验 `manifest.json` → 复制到 `%APPDATA%\AIWorkGate\plugins\<插件id>\` → 建 `plugin-data\<插件id>\`。**新装默认停用**，勾选"安装后立即启用"或之后在列表里点「启用」才会启动。

zip 里的要求：

- `manifest.json` 在 zip 根目录，或在**唯一**的顶层文件夹里；
- 清单 `entry.exe` 指向的可执行文件必须真的在包里；
- `api_level` 必须是 1 或 2（当前官方插件都是 2；见 §7.1），`id` 必须是 2–32 位小写字母/数字/短横线且以字母或数字开头；
- 不支持符号链接；解压后总大小不能超过 1 GB。

### 5.2 安装（手动放目录）

宿主只在**启动时**扫描一次插件目录：

1. 退出宿主（托盘 → 退出）；
2. 把插件文件夹整个复制到 `%APPDATA%\AIWorkGate\plugins\<插件id>\`，确保 `manifest.json` 就在这一层；
3. 重新启动宿主，插件会出现在列表里。

当前版本**没有拖拽安装**，管理页也只接受 zip 路径。

### 5.3 权限提示

当前版本的安装流程**不会弹权限页**。安装前请自己打开插件的 `manifest.json`，看 `permissions` 字段：

| 字段 | 含义 |
|---|---|
| `read_paths` | 插件声明会读取的路径（可能含 `%USERPROFILE%`） |
| `launch_apps` | 会启动哪些外部程序（例如官方客户端） |
| `network_domains` | 会访问哪些域名 |
| `use_proxy` | 会读取 `egress.json`、走账号级代理 |
| `os_identity` | 会修改整机/客户端身份（高风险） |
| `require_admin` | 需要管理员权限运行 |

**没有沙箱**：插件以你的用户权限运行，能干你账号能干的任何事。只装你信任的插件。

### 5.4 更新

再走一次"安装"，zip 里的插件 id 相同即可：

- 替换 `plugins\<id>` 的全部文件；
- `plugin-data\<id>`（账号、缓存等）**原样保留**；
- 若插件正在运行，会先停止再重启；
- 已保存的插件设置（启动方式、并发、签到时间、严格出网）保留。

版本号只用于显示，宿主不联网检查更新。

### 5.5 停用、停止、启用、卸载

| 操作 | 效果 |
|---|---|
| 停用 | 停进程，并记住"已停用"；重启宿主也不会自动拉起 |
| 启用 | 重新拉起并记住状态 |
| 停止 | 只停这一次；"随宿主启动"的插件在下次宿主启动时还会起来 |
| 卸载 | 停进程 → 删除 `plugins\<id>` → 删除插件设置行 → **保留** `plugin-data\<id>`（插件 token 目前也保留在 `secrets.dat`，同 id 重新安装会继续使用） |

卸载后模型立即从列表消失，其他插件不受影响。要彻底清掉数据，见 §14。

### 5.6 常驻 vs 按需

- `always`（常驻）：宿主启动就拉起；
- `on_demand`（按需）：第一次模型请求、打开「账号」页、到签到/额度检查时拉起；空闲一段时间后自动退出（清单 `idle_timeout_s`，默认 600 秒 = 10 分钟）。

选择哪个由插件清单 `startup.mode` 决定；清单没写时用「设置」里的默认值。

**每个插件单独改**：插件页 → 该行「编辑」，可以设启用/停用、启动方式、并发、签到时刻、严格出网，控件旁会显示「当前生效」与「全局默认」。留空/选「跟随全局」的项回到「设置」里的默认值；这里改完立即写库并对运行中的插件热生效（并发、严格出网即时生效；启动方式与启停在下一次拉起时完全落定）。

### 5.7 崩溃与自愈

- 插件意外退出：按 1s、2s、5s、10s、30s 退避重启；
- 10 分钟内失败 5 次：标记"异常"，停止重试（日志里有 `plugin marked failed`）。在插件页点"启动/启用"可重新尝试；
- 运行中每 30 秒健康检查，连续 3 次失败按崩溃处理；
- 按需插件启动最多等 15 秒，超时客户端收到 503。

### 5.8 登录与账号管理

「账号」页右上角的「添加账号 / 登录」由宿主渲染通用登录外壳，实际登录由插件完成，宿主只转交表单值，不保存凭据。

- 按钮会按插件声明的方式显示：**浏览器登录**（`login_oauth`）、**API Key**（`login_api_key`）、**读取本机登录态**（`login_local_state`）、**Cookie 登录**（`login_cookie`）；
- 浏览器登录：点「开始登录」后打开登录页，在浏览器完成授权，页面每 2 秒自动检测，成功后关闭面板并刷新账号；5 分钟未完成会自动过期，可点「取消」；
- 读取本机登录态：适用于读取官方客户端已保存的登录信息（如 OfficeAce），需要先在本机客户端里登录；
- API Key / Cookie：按表单填写后提交，值只发送给插件。

每个账号卡片上还有：

- **停用 / 启用**：只影响宿主和插件是否使用该账号，不删除凭据；
- **刷新凭据**（插件声明 `refresh` 时显示）：立即续期一次。OfficeAce 默认**不会**自动续期，因为续期可能让 OfficeAce 自己的登录失效；需要时手动点一次，或在插件数据目录写入 `config.json {"auto_refresh": true}`；
- **删除**（内联二次确认）：删除插件内保存的账号与凭据，不会注销官方客户端。

各平台登录细节见插件目录中的 `README.md`（例如 `plugins\codearts\README.md`、`plugins\officeace\README.md`）。

### 5.9 账号健康与冷却

宿主会根据**签到失败**的原因给账号记一个健康状态，并暂停使用一段时间。这个状态存在宿主数据库里（`account_meta`），不是插件上报的，重启宿主也不会丢。

| 状态 | 界面文字 | 冷却时长 | 什么时候恢复 |
|---|---|---|---|
| `session_dead` | 登录失效 | 永久 | 成功重新登录后立即清除 |
| `banned` | 已封禁 | 永久 | 成功重新登录后清除（一般应直接换号） |
| `plan_limit` | 套餐限制 | 12 小时 | 到点自动恢复 |
| `device_signed` | 设备已签 | 到次日 00:05（本地时间） | 到点自动恢复 |
| `rate_limited` | 限流中 | 上游给了重置时间就用重置时间；否则 30 分钟起，每次失败翻倍，最长 6 小时 | 到点自动恢复 |
| `quota` | 额度不足 | 同上（有重置时间用重置时间） | 充值/到点后恢复 |

`device_signed` 有时只是宿主发现「这台设备今天已经签过」而直接跳过（签到记录里是 `skipped`），这种跳过不一定会写成账号徽标；插件明确把失败归为该类别时才会进入上表。

- **怎么归因**：插件明确上报的类别最优先；没上报时，失败消息里的 401/403 记为 `session_dead`，429 记为 `rate_limited`，出现「余额不足 / 额度不足 / 积分不足 / insufficient quota」等字样记为 `quota`。认不出的失败只累计失败次数（`failure_count`），不冷却，仍按「签到」一节的失败重试间隔再试。
- **一个账号一个徽标**：「账号」页「状态」列只显示**一个**健康结论，由宿主把两路来源合并后下发：
  1. 插件上报的凭据问题 `expired` / `invalid`（需要重新登录）；
  2. 宿主的冷却状态（上表，且冷却未到期）；
  3. 插件上报的 `rate_limited`（宿主还没形成冷却时）；
  4. 否则 `normal`（正常），插件说不清时是 `unknown`（未知）。

  冷却中时徽标后面会再跟一个灰色倒计时，例如「限流中 · 12 分钟」；鼠标悬停显示原因。倒计时每 30 秒刷新，永久冷却显示「需重新登录」。`GET /api/accounts` 的每条账号因此带两组字段：`state` / `state_source`（`plugin` 或 `host`）/ `state_detail` 是合并结论，`status_kind` / `cooldown_until` / `cooldown_reason` 保留原始冷却数据（`cooldown_until` 为 unix 秒，`9999999999` 表示永久）。「已禁用」「快照」是独立徽标，不参与健康结论。
- **冷却期间**：自动签到不会调用该账号，只在签到记录里写一条 `skipped`（消息以「冷却中：」开头）；「立即签到」同样会被拦下。网关调度也不会选中它——只对 `api_level: 2`、由宿主指定账号的池生效，L1 插件由插件自己挑号、A 的流量也不受影响。冷却属于「已知原因」的失败，到点后当天剩下的调度轮次会自动再试，不需要手动重签。
- **怎么清除**：签到成功会清掉健康状态和失败计数；定时冷却到期本来就会自动恢复。永久冷却（`session_dead` / `banned`）只有**成功重新登录**能清除——浏览器登录轮询到成功，或在登录面板提交 API Key / Cookie 成功都算。
- 网关请求失败（429、5xx、连接失败等）造成的是另一套临时的账号/模型冷却（见「账号调度中心」的「粘性、对冲与降档」），它与这里的签到健康状态分开记录，但也会写进 SQLite（`scheduler_cooldowns`），重启宿主后仍然生效。

## 6. 代理池与账号级出网
### 6.1 为什么需要

有些平台会对"同一出口 IP 登录多个账号"做风控。账号级出网让**每个账号固定走一个代理**，并且：

- 代理账密只存在宿主的 DPAPI 加密存储里；
- 插件只拿到一个本机地址 `http://127.0.0.1:<临时端口>`，拿不到代理账号密码；
- 代理连不上时请求直接失败，**绝不偷偷走直连**（否则真实 IP 就泄露了）。

### 6.2 添加与测试代理

「代理」页：

1. 添加：名称、类型（`http` / `socks5`）、主机、端口、用户名/密码（可空）、是否启用；
2. 每个启用的代理，宿主会在 `127.0.0.1` 上开一个本地转发器，端口是临时分配的（不是固定的 7901）；
3. 点"测试出口"：宿主通过该代理访问 `https://api.ipify.org?format=json`，记录出口 IP、延迟、错误和时间；
4. 停用/删除代理后，它的本地转发器关闭，使用它的账号会变为 `blocked`（严格模式）或 `direct`（非严格模式）。

**系统代理（跟随 Windows）**：列表里固定有一行 `id=system`，宿主每 30 秒读一次 Windows「设置 → 网络和 Internet → 代理」里的固定代理服务器（`http=` / `https=` / `socks=` 或 `host:port`），并把它同步成这个代理行；在 Windows 里改地址或开关即可，这里不能编辑、删除或手动创建同名行（接口返回 **409**）。

- Windows 开关关闭时该行变为停用，状态列下方写明原因；账号若绑定它，按普通「代理已停用」处理（严格模式 `blocked`，非严格模式 `direct`）。
- Windows 使用 **PAC 自动配置脚本**时不跟随：PAC 是按 URL 选路，宿主的一个转发器只能固定一个上游。状态列会提示改用固定代理服务器。
- 这个功能只是省去手抄地址，代理本身仍然要能连通；出口是否正常看账号页的「出口判定」。
- Windows 的「绕过代理」列表（`ProxyOverride`）不参与判断：账号级出网是显式的，绑定了就一律走。
- Windows 不通过这个注册表项提供代理的用户名/密码；系统代理需要认证时，请手动添加一个带账密的普通代理。

本地转发器只实现 HTTP CONNECT，且只监听 `127.0.0.1`。

### 6.3 给账号绑定代理

宿主会把"账号 → 本地转发端口"写进：

```
%APPDATA%\AIWorkGate\runtime\<插件id>\egress.json
```

插件按这个文件决定每个账号怎么出网；文件里没有代理账密。

在「账号」页每个账号的"出口代理"一行：

1. 下拉框选择 `跟随插件默认`、`直连`，或池里的某个代理；
2. 点该账号的「保存」——宿主重写 `egress.json` 并让插件重新加载，立即生效；
3. 分配了代理的账号会显示一条**出口判定**：
   - `出口正常`（附证据时间）：最近 10 分钟内有成功隧道，或 30 分钟内的「测试出口」成功；
   - `出口失败 · N 分钟前`（红色）：最近一条隧道失败，或代理已停用/被删除；此时**不再显示旧的出口 IP**，因为那个 IP 是上一次成功的，不代表现在；
   - `出口待验证`：近 10 分钟没有隧道记录，也没测过。

判定只用**近期证据**：代理修好后，新的成功隧道或一次「测试出口」就会自动恢复，不需要手动清除。调度器把这当作软过滤——出口失败的账号先让位给其它账号，但所有账号都失败时仍会尝试（证据可能过期，代理也可能刚恢复）；「概览」页会出现一条黄色提示，`/healthz` 的 `egress_failed` 也会计入。

分配会持久化：宿主重启、插件重启后仍然生效。删除或停用代理后，已分配给它的账号会显示"代理已停用"，严格模式下该账号变为 `egress_missing`。

### 6.4 严格模式

严格模式的含义：**没有分配可用代理的账号，模型请求和签到一律拒绝**，返回 `egress_missing`，绝不直连。

严格模式的来源优先级：插件自己的设置行 > 「设置」页的"严格出网模式"总开关 > 插件清单里的 `egress.strict`。切换总开关后宿主会立即重写 `egress.json` 并让插件重载，不需要重启。

> 注意：A（AI Work 助手）的三个平台没有账号级代理，严格模式对 A 的流量不生效。

### 6.5 怎么确认出口 IP

- 「代理」页点"测试出口"；
- 「账号」页查看该账号绑定的代理最近一次出口 IP 和检测时间；
- 注意：检测的是**代理本身**的出口，不代表插件一定在用（还取决于 `egress.json`）。

### 6.6 A 的三家账号不能走账号级代理

A 自身没有"按账号配代理"的能力，宿主也无法替 A 隔离出口。所以 trae / workbuddy / qoder 仍然直连；要让它们也走代理，只能改 A，超出本工具范围。

## 7. 账号调度中心

当同一个平台有多个账号时，宿主会替客户端挑账号；客户端始终只用一把 Key、一个地址。

### 7.1 什么时候生效

- 模型名写成 `插件id/模型名`（如 `officeace/kimi-k2.6`）：只在这个插件内挑账号。
- 在「调度 → 模型绑定」把一个逻辑名（如 `kimi`）指向多个 `插件/模型`：逻辑模型会跨池挑选，前一个池失败自动换下一个。
- 裸模型名（如 `gpt-4o`）仍直接交给 A，不经过插件调度。
- 只有 `api_level: 2` 的插件支持"宿主指定账号"。`api_level: 1` 的插件由插件自己挑账号，账号级统计会缺失，页面会标注 L1。
- **API 级别是什么**：它不是模型/接口的版本，而是插件与宿主之间的契约代次。`v2` 表示插件接受宿主转发时附带的账号头，宿主才能把某个逻辑模型或会话固定到某个账号；`v1` 只能整池调度，宿主不指定账号；`—` 表示清单没写。资源池列表的「API 级别」列悬停也有这句说明。

### 7.2 调度页怎么用

1. **全局默认**：池间策略、默认池内策略、账号并发、池粘性、会话粘性、对冲、默认思考/降档。保存后下一个请求立即生效，不用重启。
2. **池间策略**：
   - 智能调度：按积分到期、模型倍率、剩余积分、池优先级排序；
   - 固定优先：严格按你给的池顺序，失败才回退。
3. **池内策略**（每个池可覆盖）：
   - 积分先过期优先（默认）：先花快过期的；
   - 剩余积分多优先：把消耗摊平；
   - 随机 / 三因子加权随机 / P2C 二选一：分散压力、兼顾延迟；
   - 固定优先：严格按账号优先级，适合主备关系。
4. **预设**：「最佳组合」「积分保鲜」「均匀摊销」「低延迟优先」「固定优先」一键写入所有池。
5. **模型绑定**：新建逻辑名 → 按顺序添加候选来源。客户端只要填逻辑名。
6. **解释一次调度**：填模型名（可再填会话 ID），面板会列出每个候选的分数、是否被选中、被淘汰的原因（冷却、并发、无凭据、池关闭等）。排障先看这里。

### 7.3 粘性、对冲与降档

- **池粘性**：同一模型 + 同一客户端 Key 在 TTL 内固定到同一账号，复用上游缓存。
- **会话粘性**：带 `X-Conversation-Id` 或 body 里的 `conversation_id`/`prompt_cache_key` 时优先按会话绑定。
- **对冲**：仅流式请求；首字节超过 `hedge_ms`（1000–8000）时，向下一候选并发发同一请求（带 `X-Aiworkgate-Hedge:1`），先出字者胜、另一个取消。**会产生额外上游调用**，默认关闭。
- **降档**：后台小任务（`max_tokens ≤ 128` 且短提示）或超长上下文（约 ≥100k tokens）可自动换更便宜的 flash 档；响应带 `X-Aiworkgate-Downgraded`，日志也会标记。默认关闭。
- **失败回退**：首字节前遇到 409/408/429/5xx/连接失败，会给该账号上冷却并换下一个；已出首字则把错误透传给客户端。
- **冷却跨重启保留**：请求路径产生的冷却（429 的模型/账号冷却、5xx 的账号冷却）会写入 SQLite 的 `scheduler_cooldowns`，宿主重启后自动恢复；429 的翻倍计数（strikes）一并恢复，所以下一次 429 会继续翻倍而不是从 30 秒重来，已过期的行会在启动时清掉。

### 7.4 资源页（单个插件）

- 上游开关：关闭后模型从列表隐藏，直接请求返回 503。
- 池成员：勾选参与调度的账号，清空 = 所有有凭据的账号自动入池。
- 模型目录：从插件拉取倍率、上下文、视觉、思考档位；用于池间"倍率小优先"和降档判断。每行右侧「接入」决定网关是否列出并转发该模型；插件没有上报的字段显示「—」，不猜默认值。
- 思考列显示插件真实上报的档位（关/极简/低/中/高/超高/最大），鼠标悬停可看原始档位名。CodeArts 的档位来自华为模型目录的 `thinking_config.enabled.efforts`（需登录后同步才会出现）；OfficeAce 的上游只提供"是否支持深度思考"，所以显示「关 / 开」，它的 fast/balanced/extreme 是全局档位→模型映射，不是每个模型的档位。免费标记同样只在插件给出 `is_free` 或倍率为 0 时才显示。
- **人工覆盖**：插件没上报、或上报错了的展示名/厂商/上下文/视觉/思考档位/倍率/免费，可以点该行「编辑」手动固定；保存后行尾显示「人工」徽标，鼠标悬停可看被固定的字段。同步**永远不会覆盖**人工值；点「清除覆盖」立刻回落到插件上报值。适用于插件升级后解析失效、或本地静态表对不上的情况。
- 目录同步：点「立即同步」按需拉取，按钮右侧显示「最后同步 <时间>」或「从未同步」，同步进行中时显示「同步中」徽标。失败时会出现黄色徽标「自动同步失败 N 次 · 预计 <时间> 重试」，鼠标悬停可看上次的错误摘要（URL 里的查询串与凭据会被打码）。若给该池设了「模型同步时刻」（调度参数里的 HH:MM 输入框，留空 = 不自动同步；接口是 `PUT /api/pools/<插件>`），宿主每分钟检查、每天到点自动同步一次；失败或跳过按 30 分钟、1 小时、2 小时后重试（只在当天内，最长间隔 2 小时），成功当天不再重复。`GET /api/pools/<插件>` 的响应里还带一个宿主级的同步状态汇总 `model_sync`：`last_success_at`、`last_attempt_at`、`last_error`、`failure_count`、`next_retry_at`（unix 秒，0 表示没有）和 `running`（当前是否有同步在跑）。OfficeAce 的倍率来自它本机的 `model-token-rates`；上下文/视觉/思考/厂商来自 OfficeAce 安装包内的静态模型表（只读解析，安装包更新后若解析不到就回落为「—」）。
- CodeArts 登录：`浏览器登录` 的本机回调端口会随插件重启或超时失效，浏览器可能报 `127.0.0.1 拒绝连接`。此时不必重新登录：把浏览器地址栏里的完整回调 URL 粘贴到登录面板下方（或直接选「粘贴回调地址」）即可完成；该输入框也可只填 `code`。面板会校验粘贴内容：端口对不上、或粘的是华为门户自己的网址（里面常见 `authorizationAvailable=false`），都会**立刻**告诉你原因，而不是干等超时。看到 `authorizationAvailable=false` 说明这个华为账号没有 CodeArts 授权，得先在华为云侧开通，工具这边怎么重试都没用。
- 调度参数：池内策略、并发、粘性、对冲、思考/降档，逐池覆盖全局默认。

### 7.5 当前版本边界

- 调度决策可以在「日志 → 调度」分类里看到（每个请求一条 `dispatch decision`）。
- 插件不上报每请求积分时，用量页积分列显示「—」，不做估算。
- 逻辑模型只支持 `/v1/chat/completions`；其他端点仍按裸模型路由。

## 8. 签到

### 8.1 计划时间

- 每个插件有默认签到时间（清单 `checkin.default_time`，通常是 `09:00`）；清单没写时用「设置」里的 `默认签到时间`（默认 09:00）；
- 调度器每 30 秒检查一次：到点后，对"今天还没有成功记录"的启用账号逐个签到；
- 时间一律按**本地时间**。

### 8.2 启动补签

宿主启动后的第一轮调度**不看时间**：今天还没成功签到的账号会立刻补签一次。所以电脑 10 点才开机，也不会漏。

### 8.3 失败重试

- 默认重试 2 次，间隔 5 秒、20 秒（可在「设置 → 签到」里改"失败重试次数"和间隔；次数设为 0 表示不重试，间隔列表不够长时重复最后一个值）；
- `already`（今天已签过）算成功，不重试；
- 全部失败后：记一条失败记录，并写一条通知日志。

### 8.4 一键全签

「签到」页的"一键全签"按顺序执行：

1. 所有启用插件（有 `checkin` 能力）的所有启用账号；
2. A 的三家：`trae-checkin`、`wb-checkin`、`qoder-checkin`（通过 `A.exe --task-run <任务名>` 调 A 自己的命令行）。

规则与限制：

- 手动全签**不重试**（你正看着结果）；
- 整体最多 15 分钟，单个 A 任务最多 10 分钟；
- 需要 A 的 exe 路径（设置里填，或注册表 Run 里有 A 的自启项），否则 A 的三条会直接跳过；
- A 返回的最后一行 JSON 会被解析成"成功/失败 + 摘要"；
- A 的三家结果**只显示在本次结果里**，不写进宿主的签到日历——日历只有插件账号。A 的日历请去 A 里看。

### 8.5 日历与记录保留

- 每次尝试都会写入数据库，但同一账号同一天只保留**最新一条**结果（含失败与重试）；
- 保留 **180 天**（`设置 → 保留策略` 可改）；
- 同一账号同一天多次尝试，只保留最新一条。

### 8.6 额度与提醒

- 插件声明 `quota` 能力时，宿主按其 `quota.poll_minutes` 拉取 `/accounts` 并保存快照；省略时默认每 30 分钟一次，写 `0` 表示不定时轮询（打开账号页仍会实时向插件读取额度）；
- 剩余/总额低于 10%，或没有总额时剩余低于 100，会触发一次"额度低"提醒；
- **当前版本边界**：提醒会写入宿主运行日志（`module=notify`, `kind=quota_low`）；如果在「设置 → 通知」里启用了通知并勾选了「额度不足」，还会弹出桌面系统通知，配置了地址时再额外推送到 Webhook（见「通知」一节）。

## 9. 用量与延迟

顶部导航的「用量」页按区间（7 天 / 30 天 / 自定义）看请求、积分和账号到期情况，分成「积分 / Token / 延迟分位 / 按 Key / 模型 / 到期 / 会话明细」几个标签。

### 9.1 「模型」标签

点「模型」标签，看到所选窗口内的**模型消耗排行**：

- 「最近 7 / 14 / 30 / 90 天」切换窗口，默认 30 天；
- 按请求数从高到低排列，列为：排名、模型、请求数、输入 tokens、输出 tokens、积分。积分列来自插件上报的每请求积分，插件没上报时显示「—」，不做估算；
- 当窗口内有成功的请求样本时，右侧会追加 P50、P95、TTFT P50、TTFT P95 四列：总耗时与首字节（TTFT）分位只统计 `status=200` 的成功请求，TTFT 只统计真的有首字时间的请求；没有样本的模型显示「—」；
- 排行数据来自每日汇总（`usage_daily`），延迟数据来自请求日志（`api_logs`），所以窗口上限是 90 天，且只包含已经汇总过的请求。

面板对应两个管理接口：`GET /api/usage/models?days=30`（排行）与 `GET /api/usage/latency/models?days=14`（分位），`days` 取值 1–90，缺省分别为 30 和 14。

### 9.2 连通性检测

怀疑「模型名写错 / 上游地址不通 / Key 配置不对」时，不用发真实对话，点一下检测即可，右侧会显示毫秒延迟：

- **资源页 → 模型目录**：每个模型后面有「检测」，验证该插件是否在线、模型是否仍在上报列表里。只读取插件的模型列表，**不消耗积分**；
- **首页 A 网关卡片**：「检测」探测 A 的 `/health` 与模型列表，显示「连通 · N ms」或「A 未运行或端口不可达」；
- **设置 → 自定义模型**：每行的「检测」会向上游发一条极小的 ping（`max_tokens=1`），验证地址、Key 与模型确实可用，**会产生一次极小的上游调用**；
- **设置 → 连通性诊断记录**：最近 20 条探测结果（时间、类型、目标、结果、延迟），可按 A / 插件模型 / 自定义模型筛选，记录保留 90 天。

对应的管理接口是 `POST /api/diagnostics/probe`（`kind` 取 `a`、`plugin`、`custom_model`）与 `GET /api/diagnostics/probes?limit=20`。探测失败不会改动任何配置，也不会重试或冷却账号。

## 10. 日志

### 10.1 请求日志

- 位置：SQLite（`aiworkgate.db`）+ `%APPDATA%\AIWorkGate\logs\api-YYYY-MM-DD.jsonl`；
- 内容：时间、请求 ID、来源（`a`、`plugin:<id>` 或自定义模型 `custom:<id>`）、模型名、客户端 Key、是否流式、状态码、总耗时、首字节耗时、token 数、错误摘要；
- 保留 **30 天**（「设置 → 保留策略」可改；最小 1 天）；
- 每个文件超过 10 MB 会切成 `.1`；
- **筛选**：日志页的「请求日志」卡片可沿用上方的时间范围与关键字，另加「模型」（大小写不敏感的子串）、「来源」（`a` / 插件 / 自定义模型）、「状态」（2xx / 4xx / 5xx / error）与「流式」筛选；「清除筛选」一键复位。接口 `GET /api/logs/requests` 对应参数为 `from`、`to`、`q`、`model`、`source`（或 `plugin_id`）、`account_id`（或 `account`）、`key_id`（或 `key`）、`status_class`（`2xx|4xx|5xx|error`，`error` 表示状态 0 或 ≥400）、`stream`、`limit`、`offset`；`status_class` 或 `stream` 取值非法时返回 400 `invalid_query`；
- **导出 CSV**：「导出 CSV」按钮或 `GET /api/logs/requests/export` 使用同一套筛选参数，返回带 UTF-8 BOM 的 CSV（Excel 直接打开不乱码），表头为 `时间,请求ID,来源,模型,账号,Key,流式,状态,延迟ms,首字ms,输入Token,输出Token,缓存Token`，文件名 `requests-YYYYMMDD.csv`；单次最多 50,000 行，被截断时响应头带 `X-Export-Truncated: true`；导出不含请求/响应正文与凭据；
- 过期清理在宿主启动时执行一次，之后运行中每 6 小时再执行一次；把保留天数改小后，最多约 6 小时生效。

### 10.2 运行日志

- 宿主：`logs\host-YYYY-MM-DD.jsonl`，每行 `{ts, level, module, msg, ...}`，保留 30 天；
- 插件：`logs\plugins\<插件id>-YYYY-MM-DD.log`，是插件 stdout/stderr 的逐行捕获，保留同宿主日志的天数，单文件 10 MB 轮转；
- 网页「日志」页可以切换宿主/某个插件，按行 tail，可下载；
- A 的日志不在宿主里展示，页面会提示你去 A 的设置里打开日志目录。

### 10.3 代理日志

- 位置：SQLite `proxy_logs` 表，接口 `GET /api/logs/proxy`；
- 触发条件：某个账号在「账号」页绑定了上游代理。宿主为每个**「插件 + 账号 + 代理」各开一个本机 127.0.0.1 监听**，插件只拿到这个本机地址，所以每条隧道都能归到具体账号；没绑定代理的账号（直连）不会出现在这里；
- 内容：时间、插件/账号、代理名、目标 `host:port`、结果（成功 / 拒绝 / 失败）、耗时、上行字节、下行字节、错误原因；
- 结果含义：`成功`＝隧道建成并传过数据；`拒绝`＝上游代理 refusing（鉴权失败、目标不合法、非 CONNECT 请求等，带代理返回的状态码）；`失败`＝拨号/握手没完成；
- **只记元数据**：隧道里跑的是 TLS，宿主看不到正文；代理的用户名密码也从不写进这张表；
- 保留 **7 天**（「设置 → 保留策略 → 代理日志保留（天）」可改）。因为每条隧道一行，量比请求日志大，所以窗口单独设且更短；
- 空闲的代理不占端口：监听是在写 `egress.json`（即真的有账号要用）时才建立的。

### 10.4 事件时间线

一张合并表，五个来源按时间倒序排在一起，类型按钮：`全部 / API / 代理 / 审计 / 连通性 / 运行`。

- **API**：请求日志的每个请求一条；
- **代理**：上面 10.3 的每条隧道一条；
- **审计**：`audit_log` 表。分两类显示：`审计`（状态变更，例如账号停用、删除、出口绑定、设置保存，带插件/账号与结果）和 `操作`（你在管理页点出的每一个写接口）；
- **连通性**：「设置 → 连通性自检」的探测历史（成功与失败都记），所以现在不用切到另一个面板就能看到「某个模型什么时候开始连不上」；
- **运行**：宿主 JSONL 与插件逐行日志。

时间线按**游标翻页**：工具栏显示「已加载 N 条」，滚到列表底部自动取下一页，翻到尽头显示「没有更多了」。翻页没有总量上限，不再受「每个来源最多 5 万条」限制；日志文件按字节倒着读，每页只读取需要的那一段。接口层面 `GET /api/logs/timeline` 用 `page_size` + `cursor`（上一页返回的 `next_cursor`），响应带 `has_more` / `next_cursor`；旧的 `page=2` 已移除，传了会返回 400。

失败的管理操作会带上**失败原因**，例如：

```
POST /api/accounts/patch: 5xx 1ms · plugins: http 501: this channel has a single account and cannot be disabled
POST /api/keys: 4xx 0s · invalid request: name is required
```

这条是「请求根本没进到宿主业务回调就失败」时唯一的线索来源（例如插件没实现该路由、参数校验没过）。

### 10.5 显示格式与原始行

- 工具栏的**表格 / 文本**切换三种日志的显示方式。「文本」是一行一条事件的纯文本（`时间 [来源] 摘要`），可整页复制，适合贴给别人或塞进别的日志里；选择记在浏览器本地；
- 请求表格**不显示 TTFB 与 Token 两列**（列太多，横向滚动耗时）：点行尾「原始行」展开后，摘要行会列出状态、延迟、TTFB 与 Token 入/出，`原始 JSON` 里是全量字段。「原始行」列**固定在表格右边缘**，表格再宽也不用滚到最右边才能点。
- **查看原始行**：展开时间线里的任意一条事件都可以取到它背后的一行原文——运行/插件事件取当天日志文件里的那一行 JSONL/文本，API / 代理 / 审计 / 连通性事件取对应数据库行渲染成的一条 JSON。找不到时提示「已不在保留窗口内」，不会假装是页面故障。

### 10.6 调试正文与真实 id（有隐私风险）

开关在**「日志」页顶部工具栏**（`Debug 开/关`），不在设置页里。打开后页面顶部会出现一条**常驻黄色提醒**（「调试正文已开启…」），提醒条上可以直接点「关闭 Debug」；切换标签页也不会消失，避免开着正文记录忘了关。打开后：

- 请求体最多记录 4 KB，响应体最多 8 KB，自动打码 `authorization`、`api_key`、`token`、`secret`、`cookie`、`password` 等字段和 `Bearer ...`，可以在事件里查看/下载正文；
- 管理操作日志显示**真实**的插件 id / 账号 id / 代理 id（关闭时统一写成 `{id}`），便于定位是哪一个账号出的问题；
- 无论开关如何：客户端 Key 的明文、密码、Cookie 永远不落盘；`/api/keys/<id>` 这一条路径的 id 任何情况下都保持模板化。

**只在排查问题时临时打开，查完就关。**

> **保留口径**：打开 Debug 正文后，正文按「正文预览保留天数」（默认 3 天）清理；没打开时只留一小段脱敏预览，随请求日志保留 30 天。清理在宿主启动时和运行中每 6 小时执行一次。

## 11. 规则包（指纹清洗）

### 11.1 它做什么

某些上游会按"客户端指纹"（例如系统提示词里的固定句子、`cc_` 开头的 token 参数）识别你用的是哪个 CLI。规则包做两件事：

- 字面替换：把一段固定文本换成另一段；
- 正则剥离：删掉匹配的 token 对（例如 `cc_xxx=yyy`）。

**清洗只在插件内部执行**，每个插件按自己清单里声明的规则包独立生效，没有全局开关。

### 11.2 内置规则包

宿主内置 `wb-moderation`（从 A 的 WorkBuddy 替换表移植，18 条字面替换 + 1 条 `cc_`/`x-anthropic-` 剥离正则）。它存在数据库的 `rule_packs` 表里，**只在缺失时写入**，不会覆盖你的修改。

### 11.3 文件在哪

宿主把插件声明的包合并后写到：

```
%APPDATA%\AIWorkGate\runtime\<插件id>\rules.json
```

插件通过环境变量拿到这个路径，在收到 `POST /reload` 或发现文件变化时重读。

### 11.4 在面板里编辑规则

登录面板后打开「指纹清洗」：

- 左侧列出现有规则包，右侧编辑名称、描述、字面替换对和正则；
- 「保存」后宿主重写使用该包的插件 `rules.json` 并自动 `POST /reload`；
- 自定义包可以删除；内置包（带"内置"标记）不能删除，但可以「恢复默认」把内容改回内置版本；
- 「重新加载插件规则」会把所有正在运行、且声明了规则包的插件重载一遍，页面显示重载数量。

规则包被哪些插件使用，在列表中直接标注。插件声明了不存在的规则包时，宿主合并失败、`rules.json` 不更新（宿主日志里有 `cannot write rules`）。

## 12. 设备身份

### 12.1 你能看到什么

「账号」页每个账号下方有"设备身份（只读）"：机器码、设备号、会话、身份来源（`derived` 派生 / `random` 首次随机 / `os` 来自系统级）、更新时间。

这些值由插件生成并上报，宿主**只读展示**，不会修改。

### 12.2 请求级重置

契约里插件提供 `POST /accounts/{id}/identity/reset`（`{"mode":"request"}`），只更换该账号在请求里使用的身份，不动系统。

「账号」页设备身份块里有「重置设备身份」按钮（内联二次确认）。点击后宿主调用插件的 `/identity/reset`（`mode=request`），插件通常只更换会话号，然后页面自动刷新。

插件必须声明 `identity_request` 能力；未声明时按钮仍会出现，但插件会拒绝。

### 12.3 OS 级重置（高风险）

只有声明了 `identity_os_switch` 能力且 `permissions.os_identity=true` 的插件才允许做，而且必须满足：

1. **先完全关闭对应的官方客户端**（包括托盘/后台进程），否则改了也会被覆盖或导致登录失效；
2. 需要**管理员权限**（改注册表 `MachineGuid`、IDE storage、`machineid` 文件等）；
3. 同一时间只能有一个 OS 级操作，必须**串行**执行；
4. 失败要能回滚；改完通常要重新登录。

风险：可能让本机所有同平台账号一起掉线、触发风控、影响其他软件。宿主本身永不修改 OS 身份。

### 12.4 已知限制

- **Qoder**：机器 token 来自本机原生客户端、进程级共享，同一台机器上的多个账号天然共用，这是跨账号关联通道；
- **Trae**：OAuth 设备来自本机客户端的凭据池，数量有限，服务端还限制每设备可绑账号数；
- **WorkBuddy**：本地解密依赖真实的 `Local State` + Cookies，无法只按账号伪装系统机器码。

## 13. 通知

「设置」页的「通知」卡片把签到和额度事件弹成 Windows 系统通知（桌面 toast），并可选推到手机或群机器人。启用通知后，**每个命中订阅的事件都会弹出桌面通知**（图标取自托盘图标，首次使用时转成 PNG 写到 `%APPDATA%\AIWorkGate\toast-icon.png`）；配置了地址时同一事件再额外发一个 HTTP 请求。**Webhook 地址是可选的**：没填地址时通知照常以桌面通知工作，不会报错。宿主不读取也不复用 A 的通知配置。

- **启用通知**：总开关。关闭后停止所有推送与桌面系统通知，宿主日志里的通知记录仍会保留。
- **渠道**（四选一）：
  - 「通用 Webhook（JSON）」：向地址 POST `{"title","body","kind","at"}`，适合自建接收端；
  - 「Bark（iOS）」：填 `https://api.day.app/<device_key>`，标题与内容会拼在地址路径中；
  - 「Server酱」：填完整端点 `https://sctapi.ftqq.com/<sendkey>.send`；
  - 「企业微信群机器人」：填群机器人 Webhook 地址，按文本消息发送。
- **推送事件**（可多选）：签到失败（`checkin_fail`）、签到完成（`checkin_done`）、账号失效（`account_dead`）、额度不足（`quota_low`）。签到失败按每次签到轮次汇总成一条，带首个失败原因；签到完成每个插件每天最多一条；账号失效会附上处理建议。
- **最小发送间隔**：同一类事件对同一个插件的最短间隔，范围 60–86400 秒，默认 600；签到重试失败不会刷屏。
- **通知地址**：Webhook URL 本身是凭据，以 DPAPI 加密保存在本机，**不会写入 `config.json` 或日志**；读回时只有 `url_set`（是否已保存），不回显地址。输入框留空表示保持已保存的地址；已有地址时可点「清除已保存地址」。没有保存过地址时，通知只弹桌面系统通知（不视为失败）。
- **发送测试**：卡片底部「发送测试」发一条测试消息，按钮在发送期间显示「发送中…」。桌面通知会一并弹出；只配了 Webhook 时以它的结果为准，桌面通知失败但 Webhook 成功仍算发送成功。结果会显示在「最近成功发送 / 最近错误」两行里；失败通常是地址不对或接收端拒收。
- 接口：`GET /api/notify` 读当前策略（`enabled`、`channel`、`events`、`min_interval_seconds`、`url_set`、`last_sent_at`、`last_error`），`PUT /api/notify` 保存（字段都可选，只改传了的项），`POST /api/notify/test` 发一条测试（成功返回 `{"ok":true}`，发送失败返回 502 `notify_failed`）。

## 14. 常见错误

| 现象 | HTTP / 错误码 | 原因与处理 |
|---|---|---|
| 客户端提示未授权 | 401 `invalid_api_key` | Key 没填、填错、被删除，或没带 `Bearer`。重建/重填 Key |
| A 返回 401/403 | 透传 A 的状态码 | A 的 Key 不对或过期。到「设置」重新粘贴 A Key（A 的 Key 过期需在 A 里重新生成） |
| 请求排队后失败 | 429 `concurrency_limit` | 该插件并发已满（默认 2），排队 30 秒仍无空位。稍后重试或调大并发 |
| 裸模型请求失败 | 502 `upstream_unavailable` | A 没启动，消息为"AI Work 助手未运行"。手动启动 A |
| 插件模型请求失败 | 503 `plugin_unavailable` | 按需插件冷启动失败/超时（15 秒）。看插件日志与宿主日志里的 `plugin start failed` |
| 账号请求被拒绝 | `egress_missing`（插件返回，常见 403） | 严格模式下该账号没有可用代理。配代理/关严格模式（以插件清单为准） |
| 模型不存在 | 404 `model_not_found` | 模型名写错；插件模型必须带 `插件id/` 前缀。错误消息里有可用模型 |
| 插件模型用了不支持的接口 | 501 `unsupported_endpoint` | `/v1/embeddings`、`/v1/images*` 只有 A 支持；插件模型支持 chat / completions / responses / messages |
| 用了 completions/responses 的进阶参数 | 400 `unsupported_request` | 如 `n>1`、`echo`、`logit_bias`、Responses 的 `background`；改用 `/v1/chat/completions` 或去掉该参数 |
| 浏览器里管理接口被拒 | 403 `cross_origin` / `admin_session_required` | 管理接口只接受本机同源请求 + 宿主会话 Cookie。重新加载管理页；宿主要重启过就必须重开页面 |
| 浏览器跨源调 `/v1` 失败 | 405 `cors_not_allowed` | 「设置 → 网关 / 跨源 (CORS)」里加上该网页的来源（每行一个，`*` 或 `http(s)://host:port`） |
| 打不开管理页 | — | 端口不是 7865；看 `run\gateway.port`，或宿主没启动 |
| 面板所有接口 501 | `not_implemented` | 该功能在当前版本未接线（宿主仍在开发） |

排错顺序：先看「日志」页的宿主日志（搜 `plugin`、`health`、`gateway`），再看对应插件的日志。

## 15. 卸载与数据清理

### 15.1 正常卸载

1. 托盘 → 退出；
2. 删除 exe 所在目录（程序本身没有安装器）；
3. 如果开过自启，先在「设置」里关掉"开机自启"再退出（或手动删除注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `AIWorkGate`）。

### 15.2 数据目录里有什么

`%APPDATA%\AIWorkGate\`：

| 文件/目录 | 内容 | 删了会丢什么 |
|---|---|---|
| `config.json` | 端口、A 地址、代理、调度、保留策略等非敏感设置 | 设置回到默认（端口 7865 等） |
| `secrets.dat` | DPAPI 加密：A 的 Key、客户端 Key 哈希、插件 token、局域网密码哈希、通知 Webhook 地址 | A Key、所有客户端 Key（需重建）、插件 token（插件重启后重新生成）、局域网密码、通知地址（需重填） |
| `aiworkgate.db` | 请求日志、签到历史、额度快照、Key 元数据、插件设置、规则包 | 所有历史记录与设置；内置规则包会在重启后重建 |
| `plugins\<id>\` | 插件安装文件 | 插件消失，需重新安装 |
| `plugin-data\<id>\` | 插件私有数据（账号、缓存等） | 插件的账号和登录态，需要重新添加/登录 |
| `runtime\<id>\` | 宿主生成的 `rules.json` / `egress.json` | 无影响，下次启动/重载会重建 |
| `logs\` | API/宿主/插件日志 | 历史日志 |
| `run\gateway.port` | 当前实际端口 | 无影响，下次启动重写 |

### 15.3 建议的清理方式

- 只想重置某个插件：插件页"卸载"，再去 `%APPDATA%\AIWorkGate\plugin-data\` 手动删掉 `<id>` 文件夹；
- 只想清日志：退出宿主后删 `logs\` 下的旧日期文件（或在设置里把保留天数调小）；
- 完全重置：退出宿主 → 备份 `plugin-data\`（如果需要）→ 删除整个 `%APPDATA%\AIWorkGate\` → 重新启动。

注意：`secrets.dat` 用当前 Windows 用户的 DPAPI 加密，**复制到别的电脑或别的用户下无法解密**。备份时请连同 `plugin-data\` 一起考虑。
