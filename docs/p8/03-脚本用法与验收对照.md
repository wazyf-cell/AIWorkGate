## 2 · 逐脚本用法

### 2.1 `p8-create-plugin-user.sh`

```bash
# 先看计划（不改系统）
scripts/p8/p8-create-plugin-user.sh
# 确认后执行
sudo scripts/p8/p8-create-plugin-user.sh --apply
# 换用户/路径
sudo scripts/p8/p8-create-plugin-user.sh --apply --plugin-user agp --host-user aigate
```

幂等性：用户已存在则跳过创建；目录用 `install -d -o -g -m`（已存在只校正权限，不重建内容）。
额外打印**三条"让插件进程真的换 uid"的实现路径**（systemd-run / sudoers / 静态模板）——
原因见 [00 号 §4.4](./00-P8-实施方案与取舍.md)：当前 `internal/plugins/sysproc_other.go:16`
的 `pluginProcAttr()` 返回 nil，**子进程继承宿主 uid**，不换 uid 则本脚本章节全白做。

### 2.2 `p8-verify-isolation.sh`

```bash
sudo scripts/p8/p8-verify-isolation.sh
sudo scripts/p8/p8-verify-isolation.sh --plugin-user aiworkgate-plugin --cred-dir /var/lib/aiworkgate/credentials
```

5 项检查，重点是**负向测试**：以插件用户身份真去读凭据目录，必须 `Permission denied`。
判定纪律（本机踩过坑后写死）：`test -r` 返回 **1** 才算通过；返回 2/126/127/255 说明**探测没跑成**，
一律 SKIP 而**不冒充 PASS**（Windows 11 自带 `sudo.exe`，曾被误当成换用户工具而假 PASS）。

### 2.3 `p8-artifact-lock.sh`

```bash
scripts/p8/p8-artifact-lock.sh record --id opencode-trae-auth --kind tarball \
    --file /tmp/trae-1.4.2.tgz --version 1.4.2            # dry-run，打印将写入的行
scripts/p8/p8-artifact-lock.sh record … --apply            # 真写
scripts/p8/p8-artifact-lock.sh verify --id opencode-trae-auth --file /tmp/trae-1.4.2.tgz --version 1.4.2
scripts/p8/p8-artifact-lock.sh list
```

退出码：`0` 通过 / `2` 哈希或版本不符（拒绝安装）/ `3` 无锁记录 / `4` 参数错 / `5` 文件不存在。

### 2.4 `p8-diff-plugin-versions.sh`

```bash
scripts/p8/p8-diff-plugin-versions.sh --old plugins/opencode-trae-auth --new /tmp/new-trae
# 自动更新闸门：有新增域名就 exit 2
scripts/p8/p8-diff-plugin-versions.sh --old OLD --new NEW --fail-on-new-domains
# 大插件跳过文件清单
scripts/p8/p8-diff-plugin-versions.sh --old OLD --new NEW --no-files
```

输出五段（版本 / 域名 / 文件 / `child_process` / 结论）。怎么读见 [02 号 §6](./02-完整性、版本锁定与更新策略.md)。

### 2.5 `p8-bun-hash.sh`

```bash
scripts/p8/p8-bun-hash.sh record --file /opt/aiworkgate/bin/bun --version 1.4.4 --apply
scripts/p8/p8-bun-hash.sh verify --file /opt/aiworkgate/bin/bun --version 1.4.4
scripts/p8/p8-bun-hash.sh audit  --path ./scripts --path /opt/aiworkgate
```

`verify` 做三件事：sha256、`--version` 自报版本交叉核对、权限（组/其他不可写）。
`--perm-override '-rwxr-xr-x'` 是给 `stat` 不可靠环境（容器伪模式、MSYS/Cygwin）用的显式入口，
**不是**生产用法。

### 2.6 `p8-systemd-check.sh`

```bash
scripts/p8/p8-systemd-check.sh                                  # 校验本卡样例
scripts/p8/p8-systemd-check.sh --unit-file /etc/systemd/system/aiworkgate-plugin@.service
scripts/p8/p8-systemd-check.sh --live                            # 追加 systemd-analyze verify（服务器）
```

静态规则 15 条（含「行尾注释」「重复 key」「MDE 必须有书面理由」「行格式必须是 [段] 或 Key=Value」四类易漏项）。

### 2.7 `p8-selftest.sh`

```bash
bash scripts/p8/p8-selftest.sh
```

一条命令跑完上面全部逻辑断言 + 全部 `bash -n`；所有写操作限制在 `mktemp -d` 内，退出即清理。

## 3 · 验收命令（服务器上照抄）

对应计划 §P8 的 5 条验收：

```bash
# 验收 1：插件进程非 root + 凭据目录对插件用户不可读
scripts/p8/p8-verify-isolation.sh
ps -o user=,pid=,cmd= -C magpie-bridge | head          # 期望：aiworkgate-plugin
stat -c '%a %U:%G %n' /var/lib/aiworkgate/credentials   # 期望：700 aiworkgate:aiworkgate
sudo -u aiworkgate-plugin ls /var/lib/aiworkgate/credentials   # 期望：Permission denied

# 验收 2：未声明域名被拒 + 日志有记录（依赖 P1-1 实现）
#   见 01 号 §8 的 24 条矩阵；最小手测：
#   在测试插件里 fetch('https://evil.example/') → 期望 403 + proxy_logs 有 denied 行

# 验收 3：篡改 tarball 后安装被拒
scripts/p8/p8-artifact-lock.sh verify --id <id> --file <被改过的.tgz>   # 期望 exit 2

# 验收 4：自动更新失败回退（依赖实现卡）
#   步骤：装 v1 → 造一个必然启动失败的新版 → 触发更新 → 期望回退到 v1 且服务可用

# 验收 5：systemctl cat 可见加固项 + 有书面取舍
systemctl cat aiworkgate-plugin@<id>.service \
  | grep -E 'NoNewPrivileges|ProtectSystem|ProtectHome|PrivateTmp|RestrictAddressFamilies|MemoryDenyWriteExecute'
systemd-analyze verify /etc/systemd/system/aiworkgate-plugin@.service
systemd-analyze security aiworkgate-plugin@<id>.service | tail -5   # 期望：曝光分较低
scripts/p8/p8-systemd-check.sh --unit-file /etc/systemd/system/aiworkgate-plugin@.service --live
```

### 4.4 开发过程中被自己的测试抓到的两个真 bug（记下来防复发）

| bug | 现象 | 根因 | 修法 |
|---|---|---|---|
| 权限判据误判 | `chmod 755` 的 bun 被判"可写" | 用八进制子串匹配（`*7*` 命中 `755`） | 改判符号权限第 6/9 位是否为 `w` |
| 负向测试假 PASS | 插件用户"读不到凭据"被判通过 | Windows 11 的 `sudo.exe` 被当成换用户工具，退出码 2 被当成"拒绝" | 只有 `test -r` 返回 **1** 才算通过，其它一律 SKIP |
| sha256 带 `\` 前缀 | 本机算出的哈希以 `\0d2f…` 开头 | GNU coreutils 对含反斜杠的文件名整行加 `\` 转义 | `sha256_of` 里剥离前缀 |

还有一个**环境**限制（不是脚本缺陷）：MSYS/Cygwin **不映射组/其他写位**——实测 `chmod 757` 后
`stat -c %A` 仍为 `-rwxr-xr-x`。所以权限判据改用 `--perm-override` 注入符号串验证逻辑，
并在文档里写明"真实 chmod 语义未验"，不伪造成"已在 Linux 验证"。
