## 1 · 一句话结论

插件只能访问**其 manifest 声明过的域名**，声明之外一律拒绝并记一条可审计的记录；
「拒绝」必须在**两个层面**同时成立 —— 宿主侧 L7 判定（能记账口径）+ 内核侧 L3 阻断（防绕过）。
只做其一都不成立：L7 看不见不走代理的流量，L3 无法给出域名级记账。

## 3 · 拒还是不拒：strict 的语义（必须先定，否则规则没法实现）

| `egress.strict` | 未声明域名命中时 | 用于 | 理由 |
|---|---|---|---|
| `false`（现状默认） | **WARN 放行 + 记账** | 本机（Windows，登录机）、既有 12 个 Go 插件 | 兼容：老插件没有完整域名声明，强 fail-closed 会全线不可用 |
| `true` | **拒绝 + 记账** | **服务器（公网）必须** | 服务器上插件是「别人的代码 + 我们的凭据」，放行等于白做 P8 |

**部署门禁**：服务器形态要求全部插件 `egress.strict=true`，且这一条要进 P7 上线检查单。
在 `strict=true` 下，`network_domains` **缺省或为空数组 = 拒绝一切外联**（不是"跳过检查"）。

## 4 · 校验时点：加载期拒绝坏声明，运行期拒绝坏目标

### 4.1 加载期（安装/启用插件时，一次性）

`network_domains` 的每一项都要过下面这套**语法校验**；任一项不合法 → **拒绝安装/启用**，错误信息直接指向具体条目（不允许"忽略坏条目继续"）。

| 规则 | 合法 | 拒绝 |
|---|---|---|
| 必须是非空 ASCII 主机名 | `api.trae.ai` | `""`、`"   "` |
| 只允许 `[a-z0-9.-]`（大小写归一后） | `API.Trae.AI` → `api.trae.ai` | `https://api.trae.ai`（带 scheme） |
| **禁止** scheme / 路径 / 端口 / 用户信息 | `api.trae.ai` | `api.trae.ai/v1`、`api.trae.ai:8443`、`api.trae.ai@evil.example` |
| 标签长度 1~63，总长 ≤253，不以 `-` 开头/结尾 | `a-b.example.com` | `-bad.example.com`、`a.repeat...`（空标签） |
| 至少 2 个标签 | `api.trae.ai` | `localhost`（服务器桥只允许回环到宿主监听器，不经白名单） |
| 通配符**只允许最左**且必须带点 | `*.trae.ai` | `*`、`a.*.com`、`*trae.ai`（少点）、`*.ai`（公共后缀，禁止） |
| IP 字面量：**不建议**，允许但必须精确匹配，通配符永不匹配 IP | `203.0.113.10` | `203.0.113.*` |
| 去重后数量 ≤ 64 | —— | 超过则拒绝并要求拆分插件（防"白名单变成通配"） |
| IDN：必须写成 punycode | `xn--fiqs8s.example` | `中文.example`（需先转换，避免同形字混淆） |

**为什么这么多条**：白名单的价值全在"窄"。允许 `*`、允许带路径、允许公共后缀通配，等于把白名单退化成 `allow all` 却不自知。

### 4.2 运行期（每次外联）

目标匹配规则（对 CONNECT 目标的 host 做，**不是**对 SNI、不是对 HTTP `Host` 头）：

```
normalize(host)   = lowercase(host) 去掉末尾的 "."
允许 <=> ∃ entry:
  entry 不含 '*'  →  normalize(host) == entry
  entry 形如 "*.S" → normalize(host) 以 "."S 结尾 且 normalize(host) != S
                     （即至少多一级标签：a.S ✓，a.b.S ✓，S ✗）
```

- 端口不在白名单语义内（域名不带端口），端口策略见 §5.3。
- **重定向不重新授权**：`3xx` 跳到一个未声明域名时，目标域名同样要走一次判定（否则一个声明域名就能把流量带到任意地方）。

## 5 · 强制点：三层，缺一不可

### 5.1 L7-1：宿主的 CONNECT 监听器（唯一能记账的地方）

现状（`internal/egress`）：每个 `(plugin, account)` 一个回环 CONNECT 监听器，插件通过 `HTTP(S)_PROXY` 被指过来（`internal/plugins/env.go:151` `applyDirectEgress`）。
判定插入点已核实：

```
internal/egress/forwarder.go:299-313   读 CONNECT、拒绝非 CONNECT
internal/egress/forwarder.go:320-333   ← target 解析出 host / port（host:port 已在手）
internal/egress/forwarder.go:337       ← dialUpstream（判定必须在这之前）
internal/egress/forwarder.go:344-353   ← 已有 ProxyResultDenied 分支与 logRow（复用）
```

**实现要求**：在 `:333` 与 `:337` 之间插入 `whitelist.Check(pluginID, host, port)`；
不通过 → `writeHTTPError(client, 403, reason)` + `logRow(model.ProxyResultDenied, 403, reason, 0, 0)` + `return`。
**不许**回落到直连（`internal/egress/direct.go:19-22` 的注释已经明确"没有隐藏的第二条出口"）。

### 5.2 L7-2：桥内进程级拦截（P1-1）

magpie 插件只 import `node:*`（F-01），而 **Node 的 `https`/`net` 不会读 `HTTP_PROXY` 环境变量**。
所以白名单要真正覆盖 `node:https` 请求，桥必须在加载插件前改写：

- `globalThis.fetch`（undici）→ 强制走宿主监听器；
- `node:https.request` / `node:http.request` → 同上；
- 记录 `(plugin, host, allowed/denied, 时间)` 供 §6 记账。

**为什么要两层**：L7-1 只有插件"愿意走代理"时才看得见。桥内改写的意义是把"愿意"变成默认。
如果某插件用了我们没拦住的路径（`node:tls` 直连、`node:dgram`、原生 socket）→ 由 L3 兜底。

### 5.3 L3：内核侧按 uid 阻断（唯一的"不能绕过"）

```
# 概念示意：插件用户只能到回环（宿主监听器），其余一律不可达
nft add rule inet filter output meta skuid aiworkgate-plugin ip  daddr 127.0.0.0/8  accept
nft add rule inet filter output meta skuid aiworkgate-plugin ip6 daddr ::1          accept
nft add rule inet filter output meta skuid aiworkgate-plugin drop
```

- 端口策略配套：宿主监听器放行回环**任意端口**（端口是每 account 动态分配的），插件侧对外只可能经监听器。
- 因此"只允许 443/80"这条**由 L7-1 执行**（否则插件会去连 `:22`、`:6379` 之类），L3 负责"连不到"。
- ⚠️ 这条规则的前提是 `aiworkgate-plugin` 这个 uid 真的被用到（见 00 号 §4.4：当前宿主 spawn 不换 uid，此规则会是空转）。

## 6 · 拒绝与记账语义（可审计是这套设计的另一半）

### 6.1 拒绝原因码（固定枚举，写进日志，供告警聚合）

| 码 | 触发 | HTTP 语义 |
|---|---|---|
| `EGRESS_NO_DECLARATION` | strict 模式下 manifest 未声明任何域名 | 403 |
| `EGRESS_DOMAIN_NOT_DECLARED` | 目标 host 不在白名单 | 403 |
| `EGRESS_PORT_FORBIDDEN` | host 通过但端口不是 443/80 | 403 |
| `EGRESS_PRIVATE_ADDRESS_BLOCKED` | host 解析到私网/保留地址（SSRF 防护，见 §7-⑥） | 403 |
| `EGRESS_BAD_TARGET` | CONNECT 目标不是合法 `host:port` | 400（现有行为） |
| `EGRESS_UPSTREAM_DENIED` | 上游以授权错误拒绝（现有 `connectRefusedError`） | 透传 |

### 6.2 记账口径（防泄漏 + 防日志洪泛）

写 `proxy_logs`（现有表，`model.ProxyResultDenied` 已存在）：

| 记什么 | 不记什么 |
|---|---|
| `plugin_id`、`account_id`、`proxy_id`、`result=denied`、`status`、`reason_code`、`host`、`port`、`ts` | **不记** URL path、query、请求头、正文、凭据、SNI 原文 |
| 同一 `(plugin, host, reason)` **每分钟最多 1 条明细**，其余只累加计数 | 不逐条写（否则一个投毒插件能用日志把盘写满，反而成 DoS） |

### 6.3 告警

- 任意 5 分钟内 `EGRESS_DOMAIN_NOT_DECLARED` > 10 → 面板红点 + 记事件（插件可能被投毒或有隐藏 telemetry）。
- `EGRESS_PRIVATE_ADDRESS_BLOCKED` **出现即告警**（正常插件没有理由访问 `127.0.0.1`/`10.0.0.0/8`/`169.254.169.254`）。
- `EGRESS_NO_DECLARATION` 出现 → 说明有插件在 strict 模式下从没声明过域名，按"该插件不可用"处理，不要静默改配置放行。

## 7 · 已知绕过面（写清楚，避免把白名单当银弹）

| # | 绕过手法 | 现状 | 处置 |
|---|---|---|---|
| ① | 插件绕过代理直连（`node:tls`、原生 socket、`child_process` 起 curl） | L7 看不见 | **L3 阻断**（§5.3）+ 更新差异摘要盯 `child_process`（02 号） |
| ② | 用 `child_process` 起子进程继承宿主环境 | 子进程 uid 同宿主 | L3 按 uid 阻断在**没有换 uid 时失效**（00 号 §4.4 的 H-1 必须先做） |
| ③ | 白名单写太宽（`*.ai`、`*.cloud`） | 校验期禁止公共后缀通配 | §4.1 规则 |
| ④ | DNS rebinding：声明域名解析到内网 IP | 目前 `dialDirect` 直接 dial（`internal/egress/direct.go:76`） | 发布前解析 → 命中私网即 `EGRESS_PRIVATE_ADDRESS_BLOCKED`；**这是必须做的 SSRF 防护** |
| ⑤ | 重定向把流量带到别处 | L7 只看 CONNECT 目标 | 3xx 目标重新判定（§4.2 末） |
| ⑥ | 非 HTTP(S) 协议（gRPC/WS 之外的自定义 TCP） | CONNECT 是 TCP 隧道，域名可见但内容不可见 | 域名判定仍然有效；内容审计不属本卡 |
| ⑦ | 声明一个"看起来正常"的中转域名 | 域名白名单无法判断目标是否恶意 | 人工审查（D-58 的安装档案）+ 更新差异摘要 |
| ⑧ | 请求里带数据到**已声明**域名的 query/path | 白名单只管 host | P10 脱敏（`internal/redact` 搬运）负责内容，不归本卡 |
