# AIWorkGate 公网部署（Linux 主机 + Caddy 反代）

本文对应 P5-6：把当前宿主部署到一台 Linux 服务器，由 Caddy 提供 HTTPS 并反代到本机回环端口。Windows 桌面版不需要本文。

## 1. 构建

在开发机（Windows 或 Linux）仓库根目录：

```bash
# 前端产物必须是最新的（npm run build 会写进 internal/webui/dist 并被 go:embed 打进二进制）
cd web && npm run build && cd ..

# 交叉编译 Linux 宿主（默认 amd64；ARM 服务器用 ARCH=arm64）
VERSION=0.1.0 bash scripts/build-linux.sh
```

产物：`build/linux-amd64/aiworkgate`（约 16 MB，ELF）与 `SHA256SUMS`。把二进制拷到服务器：

```bash
sudo install -d -o root -g root -m 0755 /opt/aiworkgate
sudo install -m 0755 build/linux-amd64/aiworkgate /opt/aiworkgate/aiworkgate
```

> 依赖说明：Linux 版已提供 `tray`（无托盘，UI 即控制面）、`winutil`（xdg-open / XDG autostart / flock 单实例）和 `secrets`（AES-256-GCM + `secrets.key` 0600）的非 Windows 实现。`secrets.dat` 在 Windows 用 DPAPI 密封，**不能跨平台搬运**；Linux 首次启动会新建空库。

## 2. 运行账户与目录

```bash
sudo useradd --system --home /var/lib/aiworkgate --shell /usr/sbin/nologin aiworkgate
sudo install -d -o aiworkgate -g aiworkgate -m 0700 /var/lib/aiworkgate
```

数据目录：`/var/lib/aiworkgate/.config/AIWorkGate/`（`APPDATA` 不存在时走 `os.UserConfigDir()`）。包含 `config.json`、`secrets.dat`、`secrets.key`、`aiworkgate.db` 等。

## 3. 管理员入口（无头环境）

无桌面时不会自动弹浏览器，且管理员令牌默认每次随机、只写在加密库里。用环境变量固定：

```bash
sudo install -d -m 0700 /etc/aiworkgate
sudo tee /etc/aiworkgate/env >/dev/null <<'EOF'
# 至少 32 字符；等同管理员会话令牌，勿外泄
AIWORKGATE_ADMIN_TOKEN=请替换为随机32位以上字符串
EOF
sudo chmod 600 /etc/aiworkgate/env
```

访问方式（推荐 SSH 隧道，不把管理页暴露到公网）：

```bash
ssh -L 7865:127.0.0.1:7865 user@server
# 本地浏览器打开：
# http://127.0.0.1:7865/?t=<上面那个令牌>
```

## 4. systemd 单元

样例见 `docs/p5/aiworkgate.service.example`，安装：

```bash
sudo cp docs/p5/aiworkgate.service.example /etc/systemd/system/aiworkgate.service
sudo systemctl daemon-reload
sudo systemctl enable --now aiworkgate
systemctl status aiworkgate --no-pager
journalctl -u aiworkgate -f
```

宿主默认端口 7865、默认只绑 `127.0.0.1`（`listen_lan=false`）。Caddy 与宿主同机时保持回环即可。SIGTERM 已处理，`systemctl stop` 会正常收尾。

> 插件 uid 级沙箱（P8-①，`plugins.sandbox_user`）需要宿主以 root 运行；上面的加固单元以普通用户运行，因此该项不生效（其余加固不受影响）。

## 5. Caddy 反代

样例见 `docs/p5/Caddyfile.example`。要点：

- Caddy 负责域名、自动证书与 HTTPS，反代到 `127.0.0.1:7865`。
- 首次启动后进管理页，在「设置 → 网关」确认：
  - **信任的反向代理**：加入 `127.0.0.1`（Caddy 与宿主同机）。否则 `X-Forwarded-For` 不被采信，限流/白名单会按 Caddy 的地址判定。
  - **允许访问 /v1 的来源 IP**：加入真实客户端网段（如 `0.0.0.0/0` 表示对公网开放，鉴权仍由客户端 Key 负责；更稳妥的是只放行你的出口 IP/网段）。
  - **服务模式**：保持 `open`；维护时切 `paused`，只给属主 Key 用时切 `whitelist`。
  - 按需设置 **每 Key / 每 IP 每分钟上限**（0 = 不限）。
- 管理页（`/`、`/assets/*`）与 `/v1/*` 在同一端口。若必须公网访问管理页，请在 Caddy 加 `basic_auth` 或 `remote_ip` 限制；更推荐只走 SSH 隧道。

## 6. 验收

```bash
# 无 Key → 401
curl -sS -o /dev/null -w '%{http_code}\n' https://ai.example.com/v1/models

# 带 Key → 200，且列表包含插件模型
curl -sS -H "Authorization: Bearer <客户端Key>" https://ai.example.com/v1/models | head -c 400

# 过期/停用 Key → 401，文案含原因（P5-1）
# paused 模式 → 503 service_paused（D-11）
```

对应计划 P5 验收：HTTPS 200、无 Key 401、`X-Forwarded-For` 伪造无效、过期 Key 401、paused 503。

## 7. 已知限制

- Linux 未做长期实跑验证（本轮仅完成交叉编译、Windows 回归与配置/密钥实现）；首次上线建议先在内网小流量观察。
- 没有托盘；开机自启用 XDG `.desktop`（管理页里切换自启会写 `~/.config/autostart`）。
- 插件 sandbox 的 uid 隔离需要 root 宿主，与 systemd 加固单元二选一。
- `secrets.key` 是本地文件保护（0600），建议服务器磁盘开启全盘加密。
