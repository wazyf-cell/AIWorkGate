## P0-2 · 管理面鉴权改为一次性启动 token（完成）

**缺陷**：`guard()` 对任何 GET 在无 cookie 时直接 `issueSessionCookie(w)`，
于是 cookie 退化为 CSRF token——本机任意进程 `GET /api/status` 即可换取全权凭据。

**最终实现**
- `internal/webui/webui.go` — `Options.SessionToken`；`guard()` **删除 GET 自动签发分支**，
  `/api` 下**所有方法**（含 GET）强制校验；`/api/session` 是唯一**免 session cookie** 的入口
  （但**不免同源校验**，见下方「比任务书更严的一点」）；
  常量 `launchTokenParam="t"`、`sessionEndpoint="/api/session"`；`LaunchToken()` 供嵌入式取回。
- `internal/webui/session.go`（新增）— `handleSession` 用 `POST /api/session?t=` 或 JSON body 兑换 cookie，
  `subtle.ConstantTimeCompare` 恒定时间比较，**token 不入日志、不回显**，错与缺返回同一个 403（不构成 oracle）。
- `internal/app/app.go` — `adminToken` 字段、启动时 `webui.NewSessionToken()` 并落 `secrets.dat`（键 `admin_launch_token`），
  `adminUIQuery()` 把 `?t=` 拼进托盘打开的 URL。
- `web/src/main.ts` — 顶层 `await` 兑换 cookie 后 `history.replaceState` 抹掉 `t`。

**验证**（本会话独立复跑）

而 `/api/session` 免检分支在 **`:453`** —— 即**会话端点仍然要过同源校验**。
知道 token 不等于可以把 cookie 交给外源网页。任务书原文把 `/api/session` 列为「唯一免检」，
实际实现只免「session cookie 校验」，不免同源校验，**这个加强是对的，保留**。

**链路（Lead 已逐行核实，非推测）**
```
gateway.go handleChat  : if g.sched != nil && g.snapshot != nil {
                             if tgt, ok := g.matchPlugin(routed); ok {
                                 g.forwardScheduled(...)      ← 命中插件也走"调度"路径
```
即：**只要宿主启用了调度器，`/<id>/<model>` 命中的插件同样走 `forwardScheduled`**，而

**当前处置（未改宿主，最小方案）**：`plugins/aichat` 在**已配置上游**时上报**一个**合成账号
