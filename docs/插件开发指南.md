# AIWorkGate 插件开发指南

> 适用宿主：AIWorkGate `0.1.0`（Windows，Go 1.26.5）
> 契约：没有单一版本号，字段按 v0.2 → v0.3 → v0.4 逐步增加；**唯一的硬兼容门是 `api_level`（1–2）**。
> 本文是**教程**；逐字段的权威定义在 [`插件格式规范.md`](插件格式规范.md)，冲突以规范与代码为准。
> 从零到可安装 zip 的标准流程见 [`插件生成契约.md`](插件生成契约.md)。
> 核查日期 2026-10-23。

---

## 1. 插件是什么

插件是一个**独立的 Windows 可执行文件**。宿主负责：

- 发现、校验 `manifest.json`；
- 分配一个空闲 loopback 端口并启动插件进程；
- 注入端口、token、数据目录、规则文件、出口文件等环境变量；
- 轮询 `/health`、崩溃后退避重启、按需启动/空闲退出；
- 把 `<插件id>/<模型名>` 的请求转发给插件；
- 捕获插件的 stdout/stderr 写入日志；
- 生成并维护 `runtime\<id>\rules.json` 与 `runtime\<id>\egress.json`。

插件负责：自己的协议、凭据、账号池、上游调用、签到、指纹清洗、设备身份。

宿主**不会**替插件保存任何账号凭据，也没有插件沙箱：插件以当前用户权限运行，代码由用户自己安装。

## 2. 先跑起来：模板插件

`examples/plugin-template/` 是一个零依赖、可编译的最小插件（id `hello`，模型 `hello-chat`）：

```powershell
cd examples\plugin-template
$env:CGO_ENABLED = "0"
go build -o hello-plugin.exe .
```

把它打包成 zip（`manifest.json` 和 `hello-plugin.exe` 在 zip 根目录，或位于唯一的顶层目录里），在宿主「插件」页**上传该 zip** 安装（`POST /api/plugins/install`，multipart 字段 `file`，可选 `enabled=true`）。安装后：

- 插件目录：`%APPDATA%\AIWorkGate\plugins\hello\`
- 私有数据：`%APPDATA%\AIWorkGate\plugin-data\hello\`
- 模型名：`hello/hello-chat`（宿主会去掉前缀再转发）
- **默认装完是停用状态**：不传 `enabled=true` 就只是落盘，回车插件列表手动启用。
- 模板声明 `startup.mode = on_demand`，启用后第一次请求会自动拉起。

## 3. 目录与数据布局

```
%APPDATA%\AIWorkGate\
  plugins\<id>\manifest.json          宿主发现的入口（安装时由 zip 解包得到）
  plugins\<id>\<entry.exe>            必须存在，相对路径
  plugin-data\<id>\                   插件私有数据，更新不覆盖，卸载默认保留
  runtime\<id>\rules.json             宿主合并后的规则包
  runtime\<id>\egress.json            账号 -> 本地出口转发器端口（不含代理账密）
  logs\plugins\<id>-YYYY-MM-DD.log    宿主捕获的 stdout/stderr
```

安装来源（`internal/plugins/install.go`）：

- 只接受 **zip 上传**（管理页「插件」页选择文件；接口是 `POST /api/plugins/install`，multipart 字段 `file`，可选 `enabled`）。旧的「填服务器本地路径」形式因为可以指向任意可读文件、UNC 路径还会泄露本机 NTLM 凭据，已经删除。
- zip 里 `manifest.json` 可以在根目录，也可以在**唯一**的顶层目录中；`__MACOSX` 与以 `.` 开头的目录会被忽略。
- 拒绝符号链接、绝对路径、`..` 逃逸、含 `:` 的条目；解压后总大小上限 1 GiB。
- 安装是"暂存目录 + 原子改名"：先停旧进程，再替换 `plugins\<id>`，`plugin-data\<id>` 不动。
- **新装默认停用**（`enabled=false`）；更新则保留原来的启用状态。
- 启动进程时工作目录 = `plugins\<id>`。

手动安装（不用 zip）：把插件目录复制到 `%APPDATA%\AIWorkGate\plugins\<id>\`，然后**重启宿主**——宿主只在启动时扫描一次 `plugins\`，管理页没有"重新扫描"按钮。

## 4. `manifest.json`

宿主读取上限 1 MiB，未知字段忽略。校验逻辑见 `internal/plugins/manifest.go`。

```json
{
  "id": "hello",
  "name": "Hello 模板插件",
  "version": "0.1.0",
  "api_level": 1,
  "description": "最小插件模板：一个模型、流式/非流式对话、tools 回显",
  "author": "",
  "homepage": "",
  "os": ["windows"],
  "capabilities": [
    "upstream", "accounts", "checkin", "quota",
    "login_api_key", "login_oauth", "login_paste_code",
    "login_ide_plugin", "login_local_state", "login_cookie",
    "refresh", "egress", "identity_request"
  ],
  "permissions": {
    "read_paths": [],
    "launch_apps": [],
    "network_domains": [],
    "use_proxy": true,
    "os_identity": false,
    "require_admin": false
  },
  "egress": { "strict": false },
  "models": [
    { "id": "hello-chat", "name": "Hello Chat", "context_length": 8192, "tools": true, "vision": false }
  ],
  "checkin": { "default_time": "09:00" },
  "quota": { "poll_minutes": 1 },
  "concurrency": { "suggested": 2 },
  "rules": { "packs": [] },
  "startup": { "mode": "always", "idle_timeout_s": 600 },
  "entry": { "exe": "hello-plugin.exe", "args": [] }
}
```

| 字段 | 必填 | 规则 / 宿主行为 |
|---|---|---|
| `id` | 是 | 正则 `^[a-z0-9][a-z0-9-]{1,31}$`（2–32 字符）。决定目录名、模型前缀 `id/` |
| `name` | 建议 | 仅展示 |
| `version` | 建议 | 仅展示。宿主**不比较大小**、不查更新、不要求最低版本 |
| `api_level` | 是 | **1 或 2**（`model.APIVersion`，宿主接受 `MinAPILevel`–`MaxAPILevel`）。`2` 表示支持宿主指定账号（`X-Aiworkgate-Account`） |
| `description` / `author` / `homepage` | 否 | 仅展示 |
| `os` | 否 | 非空时必须包含 `windows`（大小写不敏感） |
| `capabilities` | 否 | **拼错不会被拒装**，宿主发现插件时会写一条 `plugin declares unknown capabilities` 告警，但该能力永不匹配。真正改变宿主行为的只有 `checkin`（是否参加签到）、`quota`（是否轮询额度）、`egress`（出口变化后是否给发 `/reload`）、`identity_os_switch`（配合 `permissions.os_identity`）、`login_*`（登录方式）；`upstream` / `accounts` / `identity_request` 目前**不 gate 任何东西**；`embeddings` / `images` 是保留名，宿主对插件模型一律 501 |
| `permissions` | 否 | 安装时**不弹权限页**，宿主**不读也不执行**这些字段（`os_identity` 除外）。字段：`read_paths`、`launch_apps`、`network_domains`、`use_proxy`、`os_identity`、`require_admin`。无沙箱 |
| `egress.strict` | 否 | 该插件默认严格出网；与全局 `plugins.strict_egress` 取**或**，插件设置行可显式覆盖 |
| `models` | 否 | 静态模型表，**优先于**插件的 `/v1/models`。`id` 必须匹配 `^[A-Za-z0-9._:-]+$`（不含 `/`，禁止中文）；`name` 可中文。为空时宿主**懒加载** `/v1/models`（缓存 30 秒、单次 3 秒超时） |
| `checkin.default_time` | 否 | `HH:MM`，本地时间。**非法值直接安装失败**（`checkin.default_time "..." must be HH:MM`），不会回退到宿主设置 |
| `checkin.supports_history` | 否 | 清单可写，宿主当前**不读取** |
| `quota.poll_minutes` | 否 | 省略 = 30 分钟；`0` = 不定时轮询；其余按分钟数。账号数据另有调度快照每 10 秒读一次 `/accounts`（5 秒超时） |
| `concurrency.suggested` | 否 | 0–32；0 表示用宿主默认（`plugins.concurrency`，默认 2）。实际并发以插件设置为准，夹取 1–32 |
| `rules.packs` | 否 | 声明使用的规则包名（**不校验格式**）；`[]` = 不启用清洗。包名不存在时规则文件不更新，只告警，插件照常启动 |
| `startup.mode` | 否 | `always` / `on_demand`；**为空会被规范化成 `always`**，不跟随全局 `plugins.startup_mode` |
| `startup.idle_timeout_s` | 否 | 按需空闲多少秒后退出；`<=0` 用 600，负数拒绝 |
| `entry.exe` | 是 | 相对插件目录，不得为绝对路径、不得含盘符/`:`；复制完成后必须存在且是普通文件 |
| `entry.args` | 否 | 原样作为命令行参数传给 exe |

## 5. HTTP 契约

### 5.1 基本约定

- 必须监听 `AIWORKGATE_PLUGIN_PORT`，**不要写死端口**。绑 `127.0.0.1`、`0.0.0.0`、`::` 都接受，但这是本机接口，绑 `127.0.0.1` 最稳。
- **5 秒内**必须完成监听，且宿主会用 `netstat -ano` + 父进程链确认监听者确实是它拉起的子进程；不通过就**不下发 token**（插件拿不到 token，随后 `/health` 全 401）。
- 宿主调用插件时带 `Authorization: Bearer <AIWORKGATE_PLUGIN_TOKEN>`（包括 `/health`）。宿主**不替你校验**，插件必须校验，否则任何本机进程都能调用。
- 错误体统一为：

```json
{"error":{"message":"...","type":"...","code":"..."}}
```

- JSON 响应 `Content-Type` 用 `application/json; charset=utf-8`；SSE 用 `text/event-stream; charset=utf-8` 并及时 flush。
- 单次响应上限：宿主读取 8 MiB（控制类调用）。

### 5.2 核心端点

#### `GET /health`

启动时每 100 ms 轮询一次，最多等 **15 秒**；运行期每 **10 秒**一次，超时 **2 秒**。判定规则：

- HTTP 2xx 才算健康；
- 若响应是 JSON 且含 `"ok": false` → 不健康；
- 若含 `"status"` 且不等于 `ok`（大小写不敏感）→ 不健康；
- **连续 2 次**失败 → 宿主杀掉并重启插件（约 20 秒内发现）。
- `/health` 要便宜：它每 10 秒被调一次，别在里面打上游。

```json
{"ok":true,"version":"0.1.0","uptime_s":123}
```

#### `GET /meta`

```json
{
  "id": "hello",
  "name": "Hello 模板插件",
  "version": "0.1.0",
  "api_level": 1,
  "capabilities": ["upstream"],
  "account_count": 0,
  "uptime_s": 42,
  "started_at": 1760000000
}
```

宿主在插件页点「自述」时调用它（`GET /api/plugins/{id}/meta`，**5 秒**超时，插件须在运行）；它不在轮询路径上，`/health` 才是。多余字段原样显示在「原始 JSON」里。

#### `GET /v1/models`

返回**插件内本地模型名**（不带 `<id>/` 前缀）。宿主接受三种形态：`{"data":[...]}`、`{"models":[...]}`、裸数组；每项支持 `id`、`name`、`display`、`context_length`、`context_window`、`tools`、`vision`、`supports_image`，以及契约 v0.3 的 `vendor`、`multiplier`、`thinking`（思考档位数组，如 `["off","low","high","max"]`）、`free`。含 `/` 的 id 会被丢弃。**没上报的字段宿主一律显示「—」，不猜默认值**；`thinking` 只应写上游真实支持的档位，`multiplier` 为 0 视为未提供。

```json
{"object":"list","data":[{"id":"hello-chat","object":"model","created":1760000000,"name":"Hello Chat","context_length":8192,"tools":true}]}
```

> 若 manifest 写了 `models`，宿主直接使用 manifest，不再调用本端点；但 `/<id>/<model>` 请求转发前仍会用这份表校验内层模型是否存在（不存在返回 404 `model_not_found`）。

#### `POST /v1/chat/completions`

宿主行为（`internal/gateway/gateway.go`）：

1. 鉴权客户端 Key，解析 JSON body，取顶层 `model` 与 `stream`；
2. 命中 `<id>/` 前缀后，把 `model` 改写成插件内名字；tools、tool_choice、response_format、多模态 content **原样保留**；
3. 走调度器时还会改写 `model`（逻辑模型 → 物理模型、失败后降级）并可能补 `reasoning_effort`；请注意这两项不是客户端原值；
4. 把 `Authorization` / `X-API-Key` / `X-Client-Key` 换成插件 token，其余请求头尽量保留（去掉 hop-by-hop 头和 `Content-Length`），并附加 `X-Aiworkgate-Request-Id`、`X-Aiworkgate-Hedge`；`api_level=2` 时还有 `X-Aiworkgate-Account`；
5. 等待该插件的并发名额（默认 2，排队 30 秒，超时返回 429 `concurrency_limit`）；
6. 把上游响应的状态码、响应头、body **逐字节**转发；SSE 每个读块立即 flush，不改写、不缓冲；
7. **调度路径有重试**：429 / 5xx / 401 会换账号或重试（有账号池时），所以同一请求可能到你这里多次。零账号插件（`/accounts` 返回空）直接转发，不进调度器。

**端点矩阵**（客户端 → 插件）：

| 客户端调用 | 到达插件的路径 |
|---|---|
| `/v1/chat/completions` | `/v1/chat/completions`（原样） |
| `/v1/messages`（Anthropic） | 转译成 chat 后打到 `/v1/chat/completions` |
| `/v1/responses` | 转译成 chat 后打到 `/v1/chat/completions` |
| `/v1/completions` | 转译成 chat 后打到 `/v1/chat/completions`（`echo/suffix/logit_bias/best_of>1` 会被 400 拒绝） |
| `/v1/embeddings`、`/v1/images/*` | 插件模型一律 **501 `unsupported_endpoint`**，不会到达插件 |

因此插件必须支持：

- 非流式：标准 `chat.completion`，返回 `usage`（有则记录 token）；
- 流式 `"stream": true`：`data: {chunk}\n\n`，最后 `data: [DONE]\n\n`；
- tools 透传：请求里的 `tools` 原样到达插件，插件返回的 `tool_calls` 原样回到客户端（见模板 `hello_tool_call` 示例）。

最小非流式响应：

```json
{
  "id": "chatcmpl-1",
  "object": "chat.completion",
  "created": 1760000000,
  "model": "hello-chat",
  "choices": [{"index":0,"message":{"role":"assistant","content":"hi"},"finish_reason":"stop"}],
  "usage": {"prompt_tokens":1,"completion_tokens":1,"total_tokens":2}
}
```

流式块：

```
data: {"id":"chatcmpl-1","object":"chat.completion.chunk","created":1760000000,"model":"hello-chat","choices":[{"index":0,"delta":{"content":"h"},"finish_reason":null}]}

data: {"id":"chatcmpl-1","object":"chat.completion.chunk","created":1760000000,"model":"hello-chat","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":{"prompt_tokens":1,"completion_tokens":1,"total_tokens":2}}

data: [DONE]

```

### 5.3 可选端点（按能力实现）

| 方法 | 路径 | 何时被调用 | 说明 |
|---|---|---|---|
| GET | `/accounts` | **每个运行中的插件都会被周期调用**（调度快照每 10 秒、5 秒超时），与是否声明 `accounts` 无关；账号页另走 60 秒超时 | 返回 `{"accounts":[...]}`，额度内联 |
| POST | `/accounts/login` | 登录流程 | body `{"method":…}`，方法共 6 种：`api_key`/`oauth`/`ide_plugin`/`paste_code`/`local_state`/`cookie`（由 `login_*` 能力推导，或被 `manifest.login.methods` 覆盖）；返回 `session_id` 与 `status` |
| GET | `/accounts/login/{sid}` | 轮询登录状态 | `{"status":"pending"\|"need_input"\|"success"\|"failed", …}` |
| POST | `/accounts/login/{sid}/submit` | 表单类登录 | body `{"values":{"api_key":"..."}}`，返回登录状态 |
| DELETE | `/accounts/login/{sid}` | 取消登录 | 宿主把 404/405 当作"未实现"，视为成功 |
| PATCH | `/accounts/{id}` | 启用/停用账号 | body 如 `{"enabled":false}` |
| DELETE | `/accounts/{id}` | 删除账号及凭据 | |
| POST | `/accounts/{id}/checkin` | 定时签到 / 一键全签 | 超时 **5 分钟** |
| POST | `/accounts/{id}/refresh` | "立即续期" | |
| POST | `/accounts/{id}/identity/reset` | 管理页「重置身份」 | body `{"mode":"request"\|"os"}`；OS 级需 `identity_os_switch` 能力 + `permissions.os_identity`，且插件须在运行 |
| POST | `/reload` | 规则/出口文件变化后 | 重新读取 `AIWORKGATE_RULES_FILE` 与 `AIWORKGATE_EGRESS_FILE`；宿主把 404/501 当作"无此功能"忽略 |
| GET | `/v1/models?refresh=1` | 管理页「刷新模型」 | `refresh=1` 要求绕过插件自身缓存 |

账号对象（宿主解析的字段）：

```json
{
  "accounts": [{
    "id": "acc_a1",
    "label": "user-1",
    "enabled": true,
    "status": "ok",
    "added_at": 1760000000,
    "quota": {
      "remaining": 1200, "total": 5000, "reset_at": 1760050000,
      "expires_at": 1762000000, "rate_limited": false,
      "today_checked_in": true, "checked_in_at": 1760003600
    },
    "identity": {
      "machine_id": "…", "device_id": "…", "session_id": "…",
      "source": "derived", "updated_at": 1760000000
    },
    "last_error": ""
  }]
}
```

- `status` 只用 `ok / expired / invalid / rate_limited / unknown`；是否禁用看 `enabled`。**`status` 现在会进调度判据**：`expired` / `invalid` 的账号不再计入「可调度」，`/healthz` 的 `selectable` 会少一个。
- `identity.source` 只用 `derived / random / os`。
- 账号对象还有宿主会读的字段：`credential{present,expires_at,refreshable}`、`priority`、`weight`、`cooldown_until`、`model_cooldowns`、`quota.unlimited/plan`。
- 签到时 `result` 可以是 `ok / already / fail / skipped`（`skipped` = 宿主自己拒绝调用，例如冷却中），无法识别的值按 `fail` 处理；`credits_before/after` 可省略，宿主只展示差值，不作为成功门槛。
- 签到结果还可带归因字段 `kind`、`reset_at`、`dedup_scope`、`device_key`，宿主据此决定冷却与设备级跳过。

```json
{"result":"ok","credits_before":1100,"credits_after":1200,"message":"+100","at":1760003600}
```

**注意**：宿主生成 `egress.json` **不调用插件**，而是按自己存储的账号出口分配表直接写（停机也照写），对**所有已安装插件**都写，不要求声明 `egress`。插件启动前文件已就位。

### 5.4 超时矩阵与错误码

宿主给你的超时（**你的响应必须比它快**，否则视为失败）：

| 调用 | 超时 |
|---|---|
| `GET /health` | 2s |
| `GET /accounts`（调度快照） | **5s**（每 10 秒一次，失败沿用上次缓存） |
| `GET /v1/models`（懒加载） | **3s** |
| 其余控制类调用（`/meta`、`PATCH`、`DELETE`、`/reload`、`/v1/models?refresh=1`） | 60s |
| `POST /accounts/{id}/identity/reset` | 20s |
| `POST /accounts/{id}/checkin` | **5 min** |
| `/v1/chat/completions` | 90s 首包；SSE 长时间无字节会被断开 |

客户端可能看到的错误码（由宿主产生，不是插件返回的）：

| code | HTTP | 含义 |
|---|---|---|
| `plugin_unavailable` | 503（`Retry-After: 5`） | 插件没运行/按需拉起失败 |
| `concurrency_limit` | 429 | 并发闸排队超时 |
| `model_not_found` | 404 | 内层模型不存在 |
| `upstream_error` | 502 | 插件返回 5xx 或连接失败；断代理时消息会点名代理 |
| `unsupported_endpoint` | 501 | 插件模型不支持 `/v1/embeddings`、`/v1/images` |
| `egress_missing` | — | **插件约定**：strict 下拒绝直连时自己返回，宿主不解析这个码 |

## 6. 生命周期与环境变量

### 6.1 宿主注入的环境变量（`internal/plugins/env.go`）

| 变量 | 值 |
|---|---|
| `AIWORKGATE_PLUGIN_ID` | 插件 id |
| `AIWORKGATE_PLUGIN_PORT` | 必须监听的 loopback 端口（字符串） |
| `AIWORKGATE_PLUGIN_TOKEN` | Bearer token（每个插件随机，DPAPI 保存，跨重启稳定） |
| `AIWORKGATE_PLUGIN_DATA_DIR` | `%APPDATA%\AIWorkGate\plugin-data\<id>`，启动前已创建 |
| `AIWORKGATE_RULES_FILE` | `runtime\<id>\rules.json` |
| `AIWORKGATE_EGRESS_FILE` | `runtime\<id>\egress.json` |
| `AIWORKGATE_API_LEVEL` | 镜像 `manifest.api_level`（`"1"` 或 `"2"`） |
| `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`（含小写） | 三种情况会注入：① 宿主 `proxy.enabled`；② `egress.direct_logging` 打开且该插件非 strict（指向宿主直连记录监听器，并重写 `NO_PROXY`）；③ 两者都没有时不注入。**不含代理账密** |

宿主会**删除**继承环境里的所有 `AIWORKGATE_*` 变量以及同名覆盖项，防止插件看到过期 token/端口。

插件进程以 `CREATE_NO_WINDOW` 启动，没有控制台窗口；工作目录是插件安装目录。

### 6.2 启动与健康

- 分配端口 → 注入环境 → 启动 → **5 秒内**校验端口归属 → 每 100 ms 调 `/health`，最多 15 秒；
- 超时或进程提前退出都算启动失败，计入失败次数；
- 运行期每 **10 秒** `/health`，**连续 2 次**失败按"崩溃"处理。

### 6.3 崩溃退避

- 退避序列：`1s, 2s, 5s, 10s, 30s`（超出后保持 30s）；
- 统计窗口 10 分钟；窗口内第 **5** 次失败后标记 `failed`，暂时不再重启；
- 恢复方式：① 等 **10 分钟**失败窗口过期后宿主自动重试；② 管理页"启动/启用"；③ 重启宿主。

### 6.4 停止机制（Windows）

宿主停止插件时执行（`internal/plugins/sysproc_windows.go`、`supervisor.go`）：

1. `taskkill /PID <pid> /T`（**不带 `/F`**）——只对拥有窗口的进程有效，控制台插件通常收不到；
2. 等 **3 秒**；
3. `taskkill /F /T /PID <pid>` 强杀整棵进程树，再 `Process.Kill()`。

子进程会尽量加入宿主进程的 kill-on-close 作业对象：**宿主退出时插件跟着死**（入作业失败只记日志）。

宿主**不关闭插件的 stdin**。`exec.Cmd` 未设置 `Stdin`，子进程的 stdin 是 NUL 设备，读取会立刻 EOF。因此：

- **不要把 stdin EOF 当作退出信号**，否则插件启动后立刻退出；
- 可以注册 `os.Interrupt` / `syscall.SIGTERM` 用于手动运行或未来兼容，但不要依赖"优雅退出"做关键落盘——Windows 上最终往往是强杀；
- 状态要"写一次落一次"（模板与真实插件都用临时文件 + rename 原子写）。

### 6.5 按需启动与空闲

- `startup.mode = on_demand`：模型请求、账号页读取、签到/额度调用都会触发拉起；
- 首次请求最多等 15 秒，失败返回 `503 plugin_unavailable`（`Retry-After: 5`）；
- 空闲 `startup.idle_timeout_s`（默认 600 秒）后退出，后台每 30 秒检查一次；
- `/accounts`、`/meta` 等控制调用会刷新"最近使用"时间；`/health` 轮询**不**刷新。

### 6.6 日志捕获

- 宿主逐行读取 stdout 与 stderr（单行上限 1 MiB），原样写入 `logs\plugins\<id>-YYYY-MM-DD.log`，并在内存保留最近 200 行供管理页 tail；
- 插件 id 会被清洗：转小写，`[a-z0-9._-]` 之外的字符变 `_`；
- 单文件超过 10 MB 轮转，保留 `.1` … `.3` 三代；超长行截断并追加 `[truncated at N bytes]`；
- **建议**每行输出一个 JSON 对象：`{"ts":"…","level":"info","msg":"…", ...}`。宿主不解析，但网页按行展示，JSON 更易读。

## 7. `egress.json`：账号级出网

宿主为每个启用的代理（`http` CONNECT 或 `socks5`）在 `127.0.0.1:<临时端口>` 开一个**只实现 HTTP CONNECT** 的本地转发器，然后把本地 URL 写进 `egress.json`。代理账密只留在宿主 DPAPI 存储里，**文件里没有上游账密**；URL 的 userinfo 是宿主发给**你这个监听器**的随机令牌，必须原样交给 `http.ProxyURL`（它会自动带 `Proxy-Authorization`），不要自己剥掉。

```json
{
  "version": 1,
  "strict": false,
  "default": { "mode": "direct" },
  "accounts": {
    "acc_a1": { "mode": "proxy", "url": "http://<listener-token>@127.0.0.1:49321", "proxy_id": "px_1a2b3c4d" },
    "acc_a2": { "mode": "blocked" }
  }
}
```

规则：

| 项 | 要求 |
|---|---|
| `mode` | `direct` / `proxy` / `blocked`；`proxy` 但 `url` 为空时按 `blocked` 处理。**`direct` 也可能带 `url`+`proxy_id:"direct"`**（开关「直连流量也记入代理日志」时，直连也经宿主记录监听器） |
| 适用范围 | 该账号的**模型请求、签到、登录、额度刷新全部**都走指定 `url` |
| 缺失账号 | 用 `default`；宿主在严格模式下会把 `default` 从 `direct` 改成 `blocked` |
| 文件缺失 | 按"无绑定"处理；严格模式下必须视为 `blocked`，不能直连 |
| 严格模式 | `strict:true` 时，`direct` / `blocked` 账号的所有平台请求必须拒绝，返回错误码 `egress_missing` |
| 失败语义 | 已绑定代理但连接失败 → **请求失败**，绝不回退直连 |
| 更新 | 宿主改分配后重写文件并 `POST /reload`；插件也可按 mtime 自己重读 |

转发器只绑 `127.0.0.1`；上游失败直接断开，没有直连兜底；SOCKS5 用域名方式（socks5h）避免本地 DNS 泄露。

建议实现（同 `plugins/` 下的真实插件）：

- 每次请求按账号取 `EgressEntry`，`proxy` 时用 `http.Transport{Proxy: http.ProxyURL(url)}` 的**每账号独立 transport 缓存**；
- `/reload` 或文件 mtime 变化时清空 transport 缓存；
- `strict` 判定放在**每个平台请求入口**，不要只放在模型请求上。

> `strict` 的合成方式：`manifest.egress.strict || plugins.strict_egress`；插件设置页那一行只有在被**显式改过**（`StrictSet`）时才覆盖前两者。宿主改写 `egress.json` 后会调用 `POST /reload`，插件必须在该端点重读文件并清空 transport 缓存。

## 8. `rules.json`：指纹清洗规则包

宿主把插件在 `manifest.rules.packs` 里声明的包合并后写入 `runtime\<id>\rules.json`：

```json
{
  "packs": ["wb-moderation"],
  "rules": [
    { "from": "You are Claude Code, Anthropic's official CLI for Claude.", "to": "You are Claude Code, Anthropic's official CLI tool for Claude." }
  ],
  "strip": [
    { "pattern": "\\b(?:cc_|x-anthropic-)[A-Za-z0-9_-]+\\s*[=:]\\s*[^;,\\s]+[;,]?[ \\t]*" }
  ]
}
```

- 规则包存在宿主 SQLite（`rule_packs` 表），内置 `wb-moderation` 在首次启动时写入（缺失才写，不覆盖用户修改）；
- 合并顺序按 `packs` 顺序；`strip` 去重（首次出现优先）；
- 插件声明了不存在的包时，宿主合并失败：`rules.json` **不会更新**，插件仍会启动并读到旧文件；
- 宿主写文件是原子的，但插件仍需处理"文件不存在"（按无规则处理）；
- 清洗**只在插件内执行**，没有全局开关（`packs: []` 即关闭）。

实现建议：先做字面替换（`strings.ReplaceAll`），再跑正则删除；替换命中数可用于日志。

> 管理页当前没有规则编辑/恢复入口（见差异表），但插件侧仍应实现 `/reload` 与 mtime 重读，规则文件路径是稳定的。

## 9. 设备身份

| 层 | 归属 | 要求 |
|---|---|---|
| 请求级（`machine_id` / `device_id` / `session_id`） | 插件 | 按账号确定性派生，或首次随机后固定；**并发安全**（读写加锁或不可变）；在 `/accounts` 的 `identity` 中上报。宿主默认打码展示，`GET /api/accounts/identity/details?reveal=true` 才出明文并写审计 |
| OS 级（注册表 MachineGuid、IDE storage、machineid 文件等） | 插件（可选） | 必须声明 `identity_os_switch` 能力与 `permissions.os_identity=true`；宿主负责串行化与警告；同一时间只允许一个 OS 级操作 |

- 宿主**永不**修改 OS 身份，也不提供全局"重置机器码"。
- `POST /accounts/{id}/identity/reset` 的 `mode`：`request` 只换请求级身份；`os` 才动整机/客户端身份。
- 管理接口已开放：`POST /api/accounts/identity/reset`。`mode=os` 还要带 `confirm=true`，且插件必须处于运行状态，否则 400。「同一时间只允许一个 OS 级操作」由宿主串行化。
- OS 级重置前置条件（也写进用户手册）：关闭官方客户端 → 管理员权限 → 串行执行；失败要回滚并保留原值。
- 已知限制（A 平台实测，插件文档里也要写）：
  - Qoder 的 `Cosy-MachineToken/Code/Type` 来自本机原生客户端、进程级共享，同机多账号天然共用；
  - Trae 的 OAuth 设备来自本机客户端凭据池，数量有限且服务端限制每设备账号数；
  - WorkBuddy 的 Electron 解密依赖真实 `Local State` + Cookies，无法只按账号伪装 OS 机器码。

## 10. 验收清单（逐条测试项）

在 `examples/plugin-template` 或你的插件上逐条跑：

1. **安装**：管理页上传 zip，`plugins\<id>` 出现；**默认是停用状态**，手动启用后进程才起来（或安装时带 `enabled=true`）。权限页不存在，`permissions` 请人工核对。
2. **模型出现**：`GET /v1/models`（带客户端 Key）出现 `<id>/<model>`。
3. **三种请求**：非流式、`stream:true` SSE、带 `tools` 且返回 `tool_calls` 的请求都正确。
4. **账号**：表单添加两个账号后 `/accounts` 返回两个账号与内联额度。
5. **低额度提醒**：额度低于阈值时产生提醒。宿主已接通知服务：Windows toast + Webhook（generic / bark / serverchan / wecom），按事件开关、默认 10 分钟节流。
6. **签到四态**：`ok / already / fail / skipped` 都能处理，宿主记录并显示差值；`fail` 自动重试（默认 2 次、间隔 5s / 20s，可在宿主「设置 → 插件与签到」覆盖）。
7. **一键全签**：只覆盖声明 `checkin` 能力的插件，**不包含 A**。
8. **并发**：默认并发 2，第 3 个请求排队，30 秒后 429。
9. **按需**：空闲超时后退出，下一次请求能唤醒；启动失败时客户端拿到 503。
10. **日志**：请求日志可筛选、可看详情；插件日志可 tail；开调试正文后凭据被脱敏。
11. **规则**：修改规则包后插件收到 `/reload` 并生效（当前宿主没有规则编辑 UI，可用插件 `/reload` 手动验证）。
12. **出网**：用一个本地假代理验证插件确实走 `127.0.0.1:<forwarder>`；拔掉代理后请求失败而不是直连。
13. **更新**：版本升级后账号与数据不丢（`plugin-data\<id>` 保留）。
14. **停用/卸载**：模型消失，其它插件不受影响；卸载后 `plugin-data` 仍在。
15. **A 未运行**：插件模型仍可用；A 的裸模型返回 502 且消息为"AI Work 助手未运行"（网页没有"启动 A"按钮，需手动启动 A）。

## 12. 版本与兼容

- `api_level` 是唯一硬兼容门：宿主接受 `1`（插件自己挑账号）到 `2`（支持宿主用 `X-Aiworkgate-Account` 指定账号）；超出范围直接拒绝加载。仓库内 `plugins/` 下的 12 个插件**全部**声明 `2`，`examples/plugin-template` 仍是 `1`。
- 插件 `version` 只用于展示；宿主不联网检查更新，更新 = 重新安装 zip。
- 更新只替换 `plugins\<id>`，`plugin-data\<id>` 与插件 token 保留；运行中的插件会被停止后重启。
- 卸载会删除安装目录、插件设置行与插件 token，**默认保留** `plugin-data\<id>`（宿主 UI 没有"同时删除数据"选项）。同 id 重新安装会生成新 token。
- 建议：把可变的持久状态全放 `AIWORKGATE_PLUGIN_DATA_DIR`，安装目录视为只读。

## 13. 已知限制（当前实现的边界）

1. 安装只接受 **zip 上传**，没有拖拽/目录安装入口，也没有"安装时展示权限"的页面。
2. 按需插件冷启动等待 **15 秒**（与启动期健康检查同一上限）；超时客户端拿到 `503 plugin_unavailable`。
3. 签到重试由 `checkin.retry_count` / `retry_backoff_seconds` 驱动（默认 2 次、5s/20s；次数为 0 不重试；间隔不足时重复最后一个值），界面在「设置 → 插件与签到」。
4. 通知已实现（Windows toast + Webhook），按事件开关、默认 10 分钟节流；**是否真的弹到桌面取决于系统通知设置**。
5. 规则包有管理页（列表/编辑/保存/删除/恢复默认/批量重载），保存后宿主重写 `rules.json` 并调用 `/reload`。
6. `plugins.strict_egress` 作为默认值与 manifest 取或，保存后立即重写 `egress.json` 并 reload。
7. `retention.body_preview_days`（默认 3 天）**未被应用**；正文预览随请求日志一起保留（30 天）。
8. 卸载固定保留 `plugin-data\<id>`，宿主 UI 没有"同时删除数据"选项。
9. `HTTP_PROXY` 的注入只看宿主 `proxy.enabled` / `egress.direct_logging`，**与 `permissions.use_proxy` 无关**。
10. `/meta` 只由插件页的「自述」按需调用（5s 超时，不在轮询里）。`history` 能力与 `/accounts/{id}/history` 接口已从契约移除（从没有插件实现它，留着只会让作者白做）；现在声明 `history` 会触发未知能力告警。
