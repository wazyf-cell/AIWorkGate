# AIWorkGate 插件生成契约

> **结论先说**：宿主要求的**格式**早就有了，权威文件是 [`插件格式规范.md`](插件格式规范.md)
> （2026-10-23，对应宿主 v0.1.0），`plugins/*/manifest.json` 由 `TestRepositoryManifestsAreValid` 守住。
> 缺的是**生成侧**：没有打包器，也没有一条测试证明「照文档产出的 zip 真能装上」。
> 本文补这两样：一个可执行的打包器 `scripts/pack-plugin.ps1`，和一条安装门禁
> `TestContractTemplateZipInstalls`。冲突时仍以 `插件格式规范.md` 和代码为准。

---

## 1. 产物定义

一个可安装的插件 zip 必须满足：

| 项 | 要求 |
|---|---|
| 根条目 | `manifest.json` 在 **zip 根**（或唯一顶层目录下） |
| 入口 | `manifest.entry.exe` 指向的文件与 manifest 同级存在，普通文件 |
| 名称 | 全部为相对路径；无盘符、无前导 `/`、无 `..` 段、无反斜杠转义 |
| 符号链接 / 特殊文件 | **禁止** |
| 条目数 | ≤ 4096 |
| 解压总量 | ≤ 1 GiB |
| 源文件 | 不需要打进包（`*.go`、测试、README） |

宿主安装后落在 `%APPDATA%\AIWorkGate\plugins\<id>\`，`id` 取自 manifest，**不取自 zip 文件名**。
新装默认**停用**，需要用户在插件页显式启用。

## 2. 最小 manifest

```json
{
  "id": "hello",
  "name": "Hello 模板插件",
  "version": "0.1.0",
  "api_level": 1,
  "os": ["windows"],
  "capabilities": ["upstream"],
  "models": [{ "id": "hello-chat", "name": "Hello Chat" }],
  "startup": { "mode": "on_demand", "idle_timeout_s": 300 },
  "entry": { "exe": "hello-plugin.exe", "args": [] }
}
```

硬约束（违反即装不上）：

- `id` 匹配 `^[a-z0-9][a-z0-9-]{1,31}$`；
- `api_level` ∈ {1, 2}，缺失或其它值一律拒绝；
- `entry.exe` 为安全相对路径，安装后必须存在；
- `checkin.default_time` 非空时必须是 `HH:MM`（非法值直接安装失败）；
- `os` 非空时必须包含 `windows`。

其余字段与默认值见 `插件格式规范.md` §2。未知字段会被静默忽略——**写错字段名不会报错**，
所以打包器只校验上表这几项，配置块是否生效要按规范自查。

## 3. 生成步骤

```powershell
# 1) 写代码（从模板开始最省事）
Copy-Item -Recurse examples\plugin-template my-plugin

# 2) 打包（构建 + 校验一步到位）
powershell -ExecutionPolicy Bypass -File scripts\pack-plugin.ps1 -PluginDir .\my-plugin

# 产物：my-plugin\build\<id>.zip
```

打包器做什么：

1. 读 `manifest.json`，按 §2 校验 `id` / `api_level` / `entry.exe`；
2. `CGO_ENABLED=0 go build -trimpath -buildvcs=false` 产出入口 exe；
3. 只把 `manifest.json`、入口 exe 和 `-ExtraFiles` 指定的运行期文件放进 staging；
4. 以 staging 为根创建 zip（`includeBaseDirectory = false`）；
5. 重新打开 zip，用宿主安装器的同一套规则复核，再打印产物路径与条目。

参数：

| 参数 | 说明 |
|---|---|
| `-PluginDir` | 插件源码目录（默认当前目录） |
| `-Output` | 输出 zip 路径（默认 `<PluginDir>\build\<id>.zip`） |
| `-ExtraFiles assets,config.json` | 额外运行期文件/目录，相对插件目录 |
| `-PrebuiltExe path\to.exe` | 跳过 `go build`，直接用现成二进制 |
| `-SigningKey dev.key -KeyID dev` | 生成 `manifest.sig`（宿主配置了 `plugins.trusted_keys` 时必需） |

### 签名（可选，但配置了 trusted_keys 就必须）

```powershell
go run ./tools/plugin-sign -gen -key dev.key -key-id dev
# 把打印出的公钥写进 config.json 的 plugins.trusted_keys

powershell -ExecutionPolicy Bypass -File scripts\pack-plugin.ps1 `
  -PluginDir .\my-plugin -SigningKey .\dev.key -KeyID dev
```

签名覆盖 `manifest.json` 与入口 exe 的 SHA-256，签名字节串为
`<key_id>\n<manifest_sha256>\n<entry_sha256>`。改任一文件都会使安装失败。
格式与边界见 `插件格式规范.md` §11。

## 4. 安装验收

最小闭环（三条都要过）：

```powershell
# a. 安装（插件页上传 zip，或调用管理端安装接口）
# b. 启用后确认宿主看到了模型
curl.exe -s http://127.0.0.1:7865/v1/models -H "Authorization: Bearer agk_..." 
#    -> 期望出现 "hello/hello-chat"

# c. 真实转发
curl.exe -s http://127.0.0.1:7865/v1/chat/completions ^
  -H "Authorization: Bearer agk_..." -H "Content-Type: application/json" ^
  -d "{\"model\":\"hello/hello-chat\",\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}"
```

插件侧必须做到（宿主不替你检查，失败只会在请求时暴露）：

1. 监听 `AIWORKGATE_PLUGIN_PORT`（`127.0.0.1`），15 秒内 `GET /health` 返回 2xx；
2. 每个请求校验 `Authorization: Bearer $env:AIWORKGATE_PLUGIN_TOKEN`；
3. 不把 token、账号凭据写进日志（stdout/stderr 原样落盘）；
4. 状态写一次落一次（宿主停止时可能直接 `taskkill /F /T`）；
5. 不要把 stdin EOF 当退出信号（子进程 stdin 是 NUL）。

## 5. 更新与卸载

- **更新**：同一个 `id` 再装一次 → Stop → staging → 目录替换；`plugin-data\<id>` 与用户设置保留。
- **卸载**：删安装目录；`plugin-data` 是否保留由卸载参数决定（见 `internal/plugins` 的 `Uninstall`）。
- 所有 12 个内置渠道插件都是外部插件，都可卸载、都可用 zip 重装（见 `docs/评估报告-2026-10-23-实用性与缺陷.md` §2）。

## 6. 门禁

| 门禁 | 证明什么 |
|---|---|
| `go test ./internal/plugins -run TestRepositoryManifestsAreValid` | `plugins/*/manifest.json` 能过安装器校验 |
| `go test ./internal/plugins -run TestContractTemplateZipInstalls` | **按本文布局产出的 zip 真能安装**（根 manifest + 根 entry） |
| `go test ./internal/plugins -run TestSignedPackage` | 签名包可装；改 manifest/换 exe/换 key 都被拒 |
| `go test ./internal/plugins -run TestTrustedKeysRequireASignedPackage` | 配了 trusted_keys 后未签名包被拒 |
| `scripts/test-plugins.ps1` | 12 个插件 module 的测试逐个跑 |
| `scripts/pack-plugin.ps1` 自带复核 | 产物本身无越界路径、无缺入口 |

`TestContractTemplateZipInstalls` 直接读 `examples/plugin-template/manifest.json`，
所以模板与安装器不会各说各话。
