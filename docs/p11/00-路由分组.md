# 路由分组（P11，D-28）

一个组本身就是一个可路由的模型名，成员在每次调度快照时按当前模型列表重新求解。已实现：模式分组、组规则（字符/Token/图片/思考/Agent/时段）、组权重、意图规则，以及管理页编辑器（`/groups`，`GET/PUT /api/routing-groups`）。

## 配置

在 `config.json` 顶层加：

```jsonc
{
  "routing_groups": [
    {
      "id": "trae-chat",
      "display": "Trae 全部模型",
      "match": ["trae/*"]
    },
    {
      "id": "fast",
      "match": ["re:^workbuddy/.*(mini|flash)$", "trae/glm-5"],
      "rules": [
        { "name": "vision", "match": ["trae/*vision*"], "when": { "image": true } },
        { "name": "long", "match": ["trae/long-context"], "when": { "min_chars": 60000, "min_tokens": 30000 } },
        { "name": "night", "match": ["workbuddy/*"], "when": { "start_hour": 22, "end_hour": 6 } }
      ],
      "weights": { "trae/glm-5": 3, "trae/gpt-4o": 1 }
    },
    {
      "id": "smart",
      "match": ["*"],
      "intent": {
        "enabled": true,
        "upstream": "jev",
        "labels": ["simple", "hard"],
        "route": { "simple": "fast", "hard": "trae-chat" },
        "default": "fast",
        "probe_chars": 2000
      }
    }
  ]
}
```

规则（`rules`）按顺序**首个命中**生效；命中时用规则自己的 `match` 展开成员，否则用组默认 `match`。
`when` 条件为「与」关系：

| 字段 | 含义 |
|---|---|
| `min_chars` / `max_chars` | 请求 `messages` 的序列化长度区间 |
| `min_tokens` / `max_tokens` | 估算 prompt token 区间（估算器：ASCII 0.3/字符、非 ASCII 1/字符，对 messages/system/tools 的原始 JSON 计权） |
| `image` | 请求含图片（`image_url` / inline image） |
| `thinking` | 请求含 thinking / reasoning 字段 |
| `agent` | `User-Agent` / `X-Agent` 的大小写不敏感子串 |
| `start_hour` / `end_hour` | 本地小时区间 `[start, end)`，允许跨午夜（22→6） |

同样请求两次结果一致（first-match + 固定成员顺序）；`Explain` 的 reasons 会包含 `binding rule: <name>`。

`weights` 是成员级平滑加权轮询（NGINX 算法）：`1:3` 时每 4 次请求分配约 1/3 次；未列出的成员按 1 计。权重只影响“本轮先选谁”，其余成员仍按顺序作为失败重试候选。

- `id`：对外模型名，**不能含 `/` 或空白**（避免与 `插件/模型` 语法混淆）；与已有逻辑绑定同名时，显式绑定优先。
- `match`：按顺序匹配，成员顺序即来源顺序；支持：
  - 精确 id：`trae/glm-5`
  - `*` / `?` 通配整个 id（`*` 可跨 `/`）：`trae/*`、`*/gpt-4o`
  - 正则：`re:<expr>`
- `disabled: true`：保留配置但不发布。
- 组只有在解析出至少一个成员时才会出现在 `/v1/models` 与调度里。

## 意图规则（`intent`）

组启用 `intent` 后，宿主在**账号选择之前**把本轮用户输入的一段探针发给判据模型（decision upstream），用返回的标签选择另一个路由组：

- 请求：SystemOne 形状 `{state: <探针>, questions: [{id:"route", type:"choice", question, options:<labels>}]}`，走 `decision.upstreams` 中 `upstream` 指定的实例（留空取第一个），`Authorization: Bearer <key>`。
- 答案解析：顶层 `label`/`answer`，或 `answers[]` 中的 `label`/`answer`/`choice`（1 起）/`value`（字符串或序号），大小写不敏感匹配 `labels`。
- 超时 **3 秒**；超时、上游非 2xx、答案无法解析、目标组无成员 → 走 `default`（留空保持本组）。
- **指纹缓存 10 分钟**：键 = 判据上游 + 协议/模型 + 标签集 + 探针文本；同一段输入只判定一次，不重复计费。失败不缓存。
- 探针取最后一条 user 消息（兼容 OpenAI `messages`、Gemini `contents`、Responses `input`、completions `prompt`），按 `probe_chars`（默认 2000，100~20000）截断。
- 决策 reasons 会加一条 `intent: <label> → <group>`；日志 `model_requested` 保留客户端请求名，`logical_model` 记录实际命中组。
- **真实 JEV 的 choice 答案形状尚未用真 key 验证**：当前按 F-12 的 `{model, answers}` 与上述四种拼写解析，假上游单测覆盖；拿到 key 后需补一条真实验收。

## 管理页（`/groups`）

- 左侧列出组与解析后的成员预览；右侧编辑 ID/展示名/模式/权重/规则/意图。
- 保存走 `PUT /api/routing-groups`（整体替换），宿主**严格校验**后写入 `config.json`：空 ID、重复 ID、含斜杠、空模式、坏 `re:`、负长度/Token、无效小时、重复规则名、无效权重、意图标签/目标/兜底不合法都会返回 400 并保持原配置不变。
- 保存后下一次调度快照生效（快照每请求构建，通常即时）。
- 成员预览与 `universe` 来自当前模型目录（启用的 catalog 行）；模式改动后按保存结果刷新。

## 行为

- 成员 = 当前快照中 **UpstreamEnabled 且有模型列表** 的池模型。插件新增/下架模型后，下一次快照自动增删成员（测试 `TestSnapshotPublishesDynamicGroups` 锁定）。
- 客户端把组名当普通 model 用：`/v1/chat/completions` 的 `model` 填 `fast`，调度器按组成员作为候选来源，`/v1/models` 会列出该组。
- 组可以出现在 Client Key 的 `model_scope` 里，按普通模型名匹配。
