# 路由分组（P11 第一版，D-28）

当前实现的是**模式分组**：一个组本身就是一个可路由的模型名，成员在每次调度快照时按当前模型列表重新求解。尚未实现规则表、组权重、意图规则（见文末）。

## 配置

在 `config.json` 顶层加：

```jsonc
{
  "routing_groups": [
    {
      "id": "trae-chat",
      "display": "Trae 全部模型",
      "match": ["trae/*"]
    },
    {
      "id": "fast",
      "match": ["re:^workbuddy/.*(mini|flash)$", "trae/glm-5"],
      "rules": [
        { "name": "vision", "match": ["trae/*vision*"], "when": { "image": true } },
        { "name": "long", "match": ["trae/long-context"], "when": { "min_chars": 60000 } },
        { "name": "night", "match": ["workbuddy/*"], "when": { "start_hour": 22, "end_hour": 6 } }
      ],
      "weights": { "trae/glm-5": 3, "trae/gpt-4o": 1 }
    }
  ]
}
```

规则（`rules`）按顺序**首个命中**生效；命中时用规则自己的 `match` 展开成员，否则用组默认 `match`。
`when` 条件为「与」关系：

| 字段 | 含义 |
|---|---|
| `min_chars` / `max_chars` | 请求 `messages` 的序列化长度区间 |
| `image` | 请求含图片（`image_url` / inline image） |
| `thinking` | 请求含 thinking / reasoning 字段 |
| `agent` | `User-Agent` / `X-Agent` 的大小写不敏感子串 |
| `start_hour` / `end_hour` | 本地小时区间 `[start, end)`，允许跨午夜（22→6） |

同样请求两次结果一致（first-match + 固定成员顺序）；`Explain` 的 reasons 会包含 `binding rule: <name>`。

`weights` 是成员级平滑加权轮询（NGINX 算法）：`1:3` 时每 4 次请求分配约 1/3 次；未列出的成员按 1 计。权重只影响“本轮先选谁”，其余成员仍按顺序作为失败重试候选。

- `id`：对外模型名，**不能含 `/` 或空白**（避免与 `插件/模型` 语法混淆）；与已有逻辑绑定同名时，显式绑定优先。
- `match`：按顺序匹配，成员顺序即来源顺序；支持：
  - 精确 id：`trae/glm-5`
  - `*` / `?` 通配整个 id（`*` 可跨 `/`）：`trae/*`、`*/gpt-4o`
  - 正则：`re:<expr>`
- `disabled: true`：保留配置但不发布。
- 组只有在解析出至少一个成员时才会出现在 `/v1/models` 与调度里。

## 行为

- 成员 = 当前快照中 **UpstreamEnabled 且有模型列表** 的池模型。插件新增/下架模型后，下一次快照自动增删成员（测试 `TestSnapshotPublishesDynamicGroups` 锁定）。
- 客户端把组名当普通 model 用：`/v1/chat/completions` 的 `model` 填 `fast`，调度器按组成员作为候选来源，`/v1/models` 会列出该组。
- 组可以出现在 Client Key 的 `model_scope` 里，按普通模型名匹配。
