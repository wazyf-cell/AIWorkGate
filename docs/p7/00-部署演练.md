# P7 部署演练（Linux 服务器 + Caddy）

前置产物：`scripts/build-linux.sh`、`scripts/deploy-linux.sh`、`scripts/rollback-linux.sh`、`docs/p5/`（systemd/Caddy 样例）、`docs/p14/`（`/me` 页）。

> 本文是演练清单，不是已完成的部署记录。服务器、域名与安全前置未提供，因此**P7 验收尚未执行**；本地已完成的部分：交叉编译、部署/回滚脚本、dry-run 与文档。

## 0. 用户侧前置（阻塞 P7）

- [ ] 服务器（Ubuntu 22.04+，x86_64 或 arm64）+ 公网 IP
- [ ] 域名与 DNS A/AAAA 记录
- [ ] SSH 仅密钥、禁 root 密码；安全组只放 80/443（S-1/S-2）
- [ ] 宿主访问公网所需的代理/出口（按需）
- [ ] 已轮换曾暴露的令牌（githubToken 等）

## 1. 构建（开发机）

```bash
cd web && npm run build && cd ..
VERSION=0.1.0 bash scripts/build-linux.sh        # ARM 服务器：ARCH=arm64
```

检查点：`build/linux-amd64/aiworkgate` 存在，`SHA256SUMS` 已打印。

## 2. 安装与配置（服务器）

按 `docs/p5/00-公网部署与反代.md`：

- [ ] `/opt/aiworkgate/aiworkgate` + `aiworkgate` 系统用户 + `/var/lib/aiworkgate`
- [ ] `/etc/aiworkgate/env`（0600）：`AIWORKGATE_ADMIN_TOKEN`（≥32 字符）
- [ ] `/etc/systemd/system/aiworkgate.service`（样例见 `docs/p5/`）
- [ ] `/etc/caddy/Caddyfile`（样例见 `docs/p5/Caddyfile.example`：公网只放行 `/v1/* /me/* /healthz`）

## 3. 首次启动与网关设置

```bash
sudo systemctl enable --now aiworkgate
journalctl -u aiworkgate -n 100 --no-pager
ssh -L 7865:127.0.0.1:7865 user@server   # 本地打开 http://127.0.0.1:7865/?t=<token>
```

管理页里逐项确认：

- [ ] 对外域名 `public_hosts` = 你的域名（否则反代请求 403 invalid host header）
- [ ] 信任的反向代理 = `127.0.0.1`
- [ ] 允许访问 `/v1` 的来源 IP = 真实客户端网段（公网开放可 `0.0.0.0/0`，鉴权仍靠 Key）
- [ ] 服务模式 = `open`；按需设置每 Key / 每 IP 每分钟上限
- [ ] 创建客户端 Key（分享给他人的 Key 请设到期；whitelist 模式需勾「属主 Key」）

## 4. 部署与回滚脚本

```bash
# 部署（dry-run 先看命令）
bash scripts/deploy-linux.sh user@server --dry-run
bash scripts/deploy-linux.sh user@server

# 回滚（部署失败或验收不过）
bash scripts/rollback-linux.sh user@server
```

脚本行为：旧二进制保留为 `/opt/aiworkgate/aiworkgate.prev`；上传到 `/tmp` 后**校验 SHA-256**再原子替换；`systemctl restart` 后轮询 `/healthz`，失败提示回滚。

## 5. 验收（P5/P7 对位）

```bash
# 无 Key → 401
curl -sS -o /dev/null -w '%{http_code}\n' https://<域名>/v1/models
# 带 Key → 200，列表含模型
curl -sS -H 'Authorization: Bearer <key>' https://<域名>/v1/models | head -c 400
# 管理面不对外
curl -sS -o /dev/null -w '%{http_code}\n' https://<域名>/api/status     # 期望 404
curl -sS -o /dev/null -w '%{http_code}\n' https://<域名>/              # 期望 404
# Key 自助页
curl -sS -o /dev/null -w '%{http_code}\n' https://<域名>/me/            # 期望 200
```

- [ ] HTTPS 证书正常；`/v1` 200、无 Key 401
- [ ] 伪造 `X-Forwarded-For` 的直连请求无法绕过 IP 白名单/限流
- [ ] 过期 Key → 401 含具体时间；停用 Key → 401
- [ ] `paused` → 503；`whitelist` 下非属主 Key → 403
- [ ] `/me/` 可登录、只显示自己的数据、无正文
- [ ] SSE 流式在 Caddy 下逐字到达（反代关闭缓冲；样例未显式开 buffering，若异常加 `flush_interval -1`）
- [ ] 回滚演练：手动部署坏二进制 → `rollback-linux.sh` → `/healthz` 恢复
