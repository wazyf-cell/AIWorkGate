## 勘误与补充（03 号子代理回报后修正，2026-11-05 21:30）

### 勘误 1：`Usage.vue` 是 **7 个 tab，不是 6 个**
`credits / token / latency / keys / models / expiry / sessions`（`Usage.vue:25`、`:76-84`）。
**我此前各处写的「6 个 tab」漏了 `token`**——该 tab 已有「按日 token 双柱 + 调用次数折线 + 图例切换 + 点柱下钻单日」（`Usage.vue:1118-1252`），不能列为缺口。magpie 用量页是 4 个 tab（`page.js:2780`：Overview/Requests/Sessions/Context）。

### 勘误 2：三处「纯性能手法」不是用户功能，已从缺口中排除
`cold_split.go`（4 天一段配对落盘）、`page_split.go`/`effort_split.go` 的「切点前落盘」是缓存性能设计（`cold_split.go:10-18` 自述），不计入缺口。

### 补充 1：**本周可做的零成本 P1（P1-7）**
`UsageTotals` 已算出 `LatencyMSSum / TTFBMSSum / TTFBCount`（`internal/store/usage.go:33-44`、`:260-269`），但 `SummaryKPI`（`internal/usage/service.go:28-35`）只透出 6 个字段（`:118-125` 只拷 6 个）→ Overview 的 KPI 条（`Usage.vue:927-975`）**少了「平均延迟 / 平均首字」两格**。零新数据、零迁移，补两格即可。

### 补充 2：**缓存命中率分母错的根因**（解释 P1-10 为何做不出）
`prompt_tokens` 已含 cached 且不扣减 → 命中率分母虚高。修 P0-2（加 cache_write 列）时应一并修口径。

### 补充 3：**「会话明细」名不副实**（P1-2）
`sessions` tab 实为逐请求列表，全仓无 `GROUP BY conversation_id`。magpie 的会话视图有切分、跨 provider 归并、增量与上限三套规格（03 号文档 §4）。

### 优势清单确认（03 号 §17 补充 2 条）
- **A1 延迟分位（P50/P95/TTFB）**：`usage_analytics.go:99/:259/:327`（nearest-rank）+ `Usage.vue:1253-1317` 独立 tab —— **magpie 全库无延迟分位**，只有均值 `MeanTTFT`
- **A2 合并多源时间线 + SSE 实时推送 + 游标续读 + 两级截断**：`timeline.go:69/:100/:118`、`/api/logs/stream`、`Logs.vue` 5 类 12 分类 —— magpie 的请求页是纯分页表格
- **A7 签到日历网格**（`Checkin.vue:322-420`）：**可直接复用为热力图骨架**，P1-3 的最低成本实现路径
- A3 可配置保留期 + 分批清理（`cleanupBatch=5000`）；A4 正文查看 + 分级截断；A5 `usage_daily` 原子增量 rollup（游标与 upsert 同事务）；A6 到期预测 `days_left` 独立 tab
