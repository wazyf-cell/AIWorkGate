## 1. 过期账号不再算「可调度」（P0）

**症状**：minimax 插件报 `status=expired`，页面徽标「已过期」，但 `/healthz` 仍是 `selectable: 8`，调度器照旧可能选它。

**原因**：宿主快照里的 `scheduler.Account` 只有 Enabled/CredentialPresent/Remaining/Total/ExpiresAt，没有插件状态；`creditIneligibleReason` 在 `quota={}` 时 fail open。

**改动**

| 文件 | 改动 |
|---|---|
| `internal/scheduler/scheduler.go` | 新增 `Account.Status` 与 `unservableStatusReason`（`expired` / `invalid`）；`SelectableCount` 排除；`evaluateAccountsLocked` 里作为**软过滤**——只要还有一个可用候选就跳过它，全部候选都不可调度时 fail open，与积分规则一致 |
| `internal/app/scheduler_snapshot.go` | 构造 `scheduler.Account` 时填入 `Status: acc.Status` |
| `internal/scheduler/pick_status_test.go`（新） | 混合池选中可用账号且 Explain 给出理由；全池不可调度时 Pick 仍返回它 |

**验证**

- 单测：`go test ./internal/scheduler` 通过；变异证明——把软过滤去掉后 `TestPickSkipsUnservableStatusWhenUsableSiblingExists` 报 `picked "expired-pick", want ok-pick`。
- 真机：`/api/accounts` 仍是 8 条，`minimax default status=expired`；`/healthz` → `{"status":"ok","selectable":7,"total":8}`。

**副作用**：`/healthz` 语义收紧了——插件说账号过期就不再计入。若某个插件用 `expired` 表示"需要重新登录但仍可用"（目前没有这种），会被提前排除，需改插件侧语义。

## 2. 5xx 文案带出「出口/代理」这一层（P0）

**症状**：代理没开时只回 `Bad Gateway`，被读成"上游坏了"。

**改动**

| 文件 | 改动 |
|---|---|
| `internal/gateway/egress_hint.go`（新） | `EgressHintSource`（`ListAccountEgress` / `LatestProxyFailure`），10 分钟窗口、250ms 超时、最长 160 rune，URL 里的 userinfo 脱敏 |
| `internal/gateway/dispatch.go` | `writeAttempt`：`status>=500` 与传输失败（`status<200`→503）时在 **message 末尾**追加一句，结构化字段不动 |
| `internal/store/proxy_logs.go` | 新增 `LatestProxyFailure(pluginID, accountID, since)` |

**验证**（真机，opencode 绑定已停的 `127.0.0.1:7897`）：

```
502 {"error":{"code":"upstream_error","message":"upstream request failed: Post \"https://opencode.ai/inference/v1/chat/completions\": Bad Gateway；该账号经代理「系统代理」出网，最近一次隧道失败：egress: dial upstream proxy 127.0.0.1:7897: dial tcp 127.0.0.1:7897: connectex: …（0:03 前）"}}
```

**边界**：只加在给人看的 `message` 上，`code`/`type`/状态码都没变，客户端按 code 分支的逻辑不受影响；代理恢复后 10 分钟内仍可能带上一句旧失败提示（带时间戳，可自证）。

**问题**：代理功能本身是完整的（账号级绑定、本地转发器、出口健康都生效），但添加代理要手抄地址；用户问能不能"跟随系统代理"。

**先澄清一件事**：宿主没有"默认代理"这个设置——账号未绑定代理时就是直连（严格模式下 blocked），全局 `settings.proxy` 那组字段只是写给插件进程的环境变量，而插件出网模式是 `Proxy: nil`，不读环境代理。所以"自动选择一个默认代理"并不存在，也不应该凭空让所有账号共享一个出口（出口 IP 会随代理切换漂移，正是风控要避免的）。

**改动**：

- 新增 `internal/hosts/systemproxy*.go`：读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` / `ProxyServer`；支持 `host:port`、`http=/https=/socks=` 与带 scheme 的写法，IPv6 一并处理。`ProxyEnable=0` 视为未开启；PAC（只有 `AutoConfigURL`）返回专用错误。
- 新增 `internal/app/systemproxy.go`：每 30 秒（启动时先同步一次）把结果写入保留代理行 `id=system`、名称「系统代理（跟随 Windows）」，端点/开关变化时才 `upsert` 并启停转发器、重写 `egress.json`、让插件重载；健康字段（最近出口/延迟/检测时间）在同步时保留。Windows 关闭或 PAC 时该行停用，原因通过 `managed_detail` 返回。

- **不做自动选择**：按"当前哪个代理健康"给账号换出口会让同一账号的出口 IP 在代理之间跳，平台风控视角等同多地点登录。已有能力是"失败不静默回退直连 + 出口失败软过滤 + fail open"，足以避开死出口，不需要换 IP。

- **存储层 keyset 分页**：`api_logs` / `audit_log` / `proxy_logs` / `connectivity_probes` 各新增一条 `(排序时间, id)` 游标查询（`QueryAPILogsTimelinePage`、`ListAuditTimelinePage`、`QueryProxyLogsTimelinePage`、`ListConnectivityProbesTimelinePage`），条件 `<time> < ? OR (<time> = ? AND id < ?)`，`ORDER BY time DESC, id DESC LIMIT n`。时间统一换算成毫秒：api/audit 用 `CAST(unixepoch(ts,'subsec')*1000 AS INTEGER)`，proxy/connectivity 用数值列 `at` / `created_at` 乘 1000。
- **迁移 v10**：为 api_logs / audit_log 建表达式索引 `(CAST(unixepoch(ts,'subsec')*1000 AS INTEGER), id)`，proxy_logs 建 `(at, id)`，让上面的排序与游标谓词都走索引。
- **时间线重写**（`Query(filter, cursor, pageSize)`）：每个来源只取 `pageSize+1` 条，内存里只合并这一页；游标是不透明 base64 JSON（`PageCursor`），数据库来源续在 `(毫秒, id)`，文件来源续在每个文件各自的字节偏移，另带已发出的 `path|offset` 集合（按新的文件游标裁剪后**跨页保留**）。
- **文件续读按身份去重，不按时间**：第一次实现用「早于本页边界」过滤续读结果，真机走查发现两类错：一是本页被其它来源填满、这些行根本没发出过，却因为「比边界新」被丢掉（累计丢行，最终整页为空、边界变成公元 1 年、游标被判非法返回 400）；二是只保留上一页的已发集合时，乱序行会在两页后再发一次（5.3 万条走查里 1.4 万条重复、翻页不终止）。现在去重只看 `path|offset`，且集合跨页保留、按游标裁剪（偏移在新游标之上、永远读不到的行自动移除），游标大小仍有界。
- **日志文件倒序尾读**（`timeline_files.go`）：`readLinesBefore` 从文件尾按 128 KB 块回读，每页最多 1 MB / 4 MB，只解析需要的行；不再先把整天的 JSONL/插件日志读进内存。
- **取消上限**：删掉 `maxTimelinePerSource`、`maxTimelineFileLines`、`storeAuditLimit`；`Truncated` 语义改为「某个文件在本页读取预算内没读到更早的行」，游标仍会前进，继续滚动就能越过。
- **接口**：`GET /api/logs/timeline` 改为 `page_size` + `cursor`，返回 `items/page_size/has_more/next_cursor/truncated/source_counts`，去掉 `total` / `page`；`page>1` 与非法游标都返回 **400 `invalid_query`**（`logging.ErrBadCursor` 在 app 层映射）。`page_size` 上限 200。`/api/logs/proxy` 等表格接口仍是页码分页。
- **页面**：日志页时间线改用 `next_cursor` 无限滚动；工具栏文案从「共 N 条」改为「已加载 N 条」；首页出现空页但 `has_more` 为真时自动跟进（最多 5 跳），不再误报「没有匹配的日志」。
