# 导出列清单（47 列目标 vs 现有数据源）

> 冻结于 2026-11-06（D-54 / D-05「先冻结列名清单，导出只输出有真实来源的列」）。
> 47 列目标来自 magpie `ledger.go:620-624`（缺口分析 03 号 §14 记录）；本文件只做映射，不改变现有 CSV 形状。

## 先说明形状差异

magpie 的 47 列是**每请求一行**的账本 CSV。AIWorkGate 现有 `/api/usage/export` 是**按维度聚合的分段 CSV**（`section` 列区分 `series` / `account` / `timeseries` / `model`），当前表头 26 列：

```
section, day, plugin_id, account_id, display_name, requests, prompt_tokens,
completion_tokens, credits, remaining, total, expires_at, plan, daily_credits,
days_left, granularity, cache_write, cache_write_1h, cache_unknown,
reasoning_tokens, cost_usd, pricing_model, purpose, model_requested,
model_upstream, model_served
```

因此下表的「已输出」指**聚合段里存在**；请求级明细列（时间、耗时、状态、错误等）虽然 `api_logs` 有来源，但还没有逐请求 CSV 段。

## 结论与边界

- 现有导出满足「只输出有真实来源的列」：13 个目标列在聚合段里可见，另有服务端的 `account` / `model` / `key` / `timeseries` 维度。
- 未输出 ≠ 没数据：12 个 🟡 列在 `api_logs` 有值，缺的是**逐请求 CSV 段**（含时间/耗时/状态/错误/Key/账号）。若需要，下一片是新增 `section=request` 段，按同一份表头输出，而不是另起一个 47 列文件。
- 21 个 ❌ 列需要先改采集（落列）才有意义；在采集落地前导出留空会制造「有列无值」的假象，因此不输出。
- 本清单不承诺 47 列全部实现，只冻结列名与来源口径；新增数据源时按上表自动升级状态。
