# 用量三栏与导出（P13 / D-31 第一切片）

## 已落库的三列（api_logs）

| 列 | 含义 | 来源 |
|---|---|---|
| `model` | 既有列：本次实际路由到的模型名（兼容旧查询） | 路由结果 |
| `model_requested` | 客户端请求里写的 `model`（含前缀） | 请求体，鉴权/改名前 |
| `model_upstream` | 实际发给上游的物理模型 id | 调度 decision / 插件 target / A |
| `model_served` | 上游响应里自报的 `model`（可能被悄悄换成便宜模型） | 响应体 JSON 或 SSE `data:` 帧 |

- 上游未上报 `model` 时 `model_served` 为空，**不伪造**。
- SSE 取首个带 `"model"` 的帧；非流式取响应 JSON 顶层的 `model`。
- 迁移 v17，新增列均为 TEXT，旧行为 NULL。

## 价格与成本（D-31③，本切片）

`config.json` 顶层：

```jsonc
{
  "pricing": {
    "currency": "USD",
    "models": {
      "gpt-4o": { "input": 2, "output": 8, "cache_read": 1, "cache_write": 10, "multiplier": 0.8 }
    }
  }
}
```

- 单价按 **每 1M tokens**；`multiplier` 缺省 1，计算时相乘。
- 入站缓存命中部分按 `cache_read` 计，其余 prompt 按 `input` 计；输出按 `output`。
- 模型按 `served → upstream → requested → routed` 顺序查价；查不到则 `cost_usd/pricing_model` 留空，**不按 0 计**。
- 落库：migration v19 增加 `api_logs.cost_usd`、`pricing_model`；日志/增量/原始行/导出查询全部同步。
- 验证：`TestLogComputesConfiguredCost`（1000 prompt + 500 completion，价 2/8，倍率 0.8 → 0.0048）、无价留空、store 往返、大小写查价。

## 导出粒度与拆段（本切片）

`GET /api/usage/export?from=&to=&granularity=hour|day|week`：

- 粒度只影响 `timeseries` 段（小时 / 天 / 周桶），默认 `day`；非法值 400（`usage.ErrBadQuery`）。
- 周桶从**本地日历的周一**开始。SQL 只取 `substr(ts,1,10)` 再算周一：直接 `date(ts,…)` 会把带时区偏移的行先折算成 UTC，`01:10 +08:00` 会掉进上一周（回归测试抓出）。
- 单一 CSV，`section` 列区分 `series` / `account` / `timeseries` / `model`；新增列一律追加在 `days_left` 之后，不改旧列顺序。
- `timeseries` 段：`granularity` 列写桶标签（`2026-10-19T10:00` / `2026-10-19` / 周一日期），其余行留空。
- `model` 段：按 `COALESCE(model_served, logical_model, model)` 分组的请求/token/缓存/reasoning/积分/成本。
- 前端：用量页筛选行「导出粒度 小时/天/周」，只影响导出链接。
- 验证：`TestExportGranularityAndModelSections`（小时桶 + model 段）、`TestUsageTimeSeriesBuckets`（day/hour/week 桶边界，含周日与周一）、`TestParseQueryGranularityValidation`。

## Prompt 组成分析（D-55，本切片）

`POST /api/prompt/analyze`，请求体 `{"model": "可选", "body": {…请求 JSON…}}`：

- 固定六段：`system` / `tools`（工具 schema）/ `memory`（顶层 `memory`/`memories`）/ `history`（最后一条 user 之前的全部消息，含工具调用与结果）/ `user_input`（最后一条 user 消息）/ `other`（其余顶层字段，如 model、temperature）。
- 兼容 OpenAI `messages`、Anthropic `system`（字符串或 text 块）+ `messages`、Gemini `system_instruction` + `contents(parts)`、Responses `input`/`instructions`、completions `prompt`。
- token 统一估算：ASCII 0.3/字符、非 ASCII 1/字符、每条消息 +4、图片 1024；**不运行 tokenizer，响应 `estimated: true`，UI 标注「估算值，非计费 token」**。
- `model` 可显式指定，留空取请求体的 `model`；用 `model_catalog.context_length` 解析上下文窗口（精确 id，其次 `plugin/model`、`vendor/model` 后缀匹配），解析不到只返回分段、不含窗口占比。
- 上限 8 MiB（与网关入站一致），`body` 缺失/为 `null` → 400；非对象 JSON → 400。
- 前端：调度页「Prompt 组成（估算）」卡片，粘贴请求体 → 六段色条 + 表格 + 窗口占比。
- 验证：`TestAnalyzePrompt*`（OpenAI/Anthropic/Gemini/字符串 input/工具调用/非对象拒绝）、`TestFindModelContextLength`、`TestPromptAnalyze*`（app 与 webui）、视觉基线 `scheduler-prompt`。
