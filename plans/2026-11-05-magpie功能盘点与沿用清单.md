## 2 · 路由（`internal/gateway`，routing.go 2360 + fallback.go 4530 + affinity.go 1402）

### 2.1 路由模式的真实语义（`routing.go:1-12` 原文）

> 「Routing spreads a provider's requests over the keys or accounts it has on: **smartly, in order, in turn, or the least used first**. Whichever goes first, **a key that suits the request still goes before one that doesn't**, and one resting after a failure waits at the back for as long as its failure says…」

对应你截图里的 9 种。**aiworkgate 有 6 个，缺 3 个**（按顺序、免费优先、速度优先）。

### 2.2 冷却分级（**最关键的可沿用点**）

`routing.go:1-12` 原文列出了冷却时长的**按原因分级**：

| 原因 | 冷却时长 |
|---|---|
| 额度耗尽（out of credit） | **半小时** |
| 配额用完（out of quota） | **直到上游说的重置时间**（订阅则到窗口填满） |
| 限流（rate limited） | **直到上游说可以再试** |
| 其他失败 | **1 分钟，再次失败则逐次加长** |

**aiworkgate 现状**：`cooldown429Base=30s`，翻倍到 `max=600s`（`scheduler.go:364-365`）——**只有「翻倍」一种策略，不区分原因**。

**这是真实差距**：你的 codearts 额度用完后会被反复重试（每次都 doomed），而 magpie 会直接休息半小时。

### 2.3 `usageHalfLife`（`routing.go:23`）

```go
// usageHalfLife is how fast the tokens a key served stop counting against
// it when choosing by use: half of them after an hour.
const usageHalfLife = time.Hour
```

**指数衰减的「用量」权重**：1 小时前的用量只算一半。aiworkgate 的 `remaining_first` 是**静态余额比较**，没有时间衰减。

### 2.4 备用链（`fallback.go:1-15` 原文，4530 行）

> 「a provider can name models to use when it can't take a request — a coding plan out of quota, a rate limit, an overloaded or failing vendor. **The request goes to the next one only while none of the reply has been sent**, so an agent sees one clean answer from whoever gave it, never a half from each. A provider that just failed that way **waits at the back of the line for a minute**, rather than costing every request a doomed try.
> A provider with several keys on is several candidates, one per key, in order, and so is a subscription with several accounts on: **when one account runs out, the next account of the same provider takes the request before any fallback model does**.」

**三条可沿用语义**：
1. **只在「回复尚未开始」时切换**（保证答案完整，不出半个）
2. **失败者排到队尾 1 分钟**（避免每次都付一次 doomed 尝试）
3. **同 provider 多账号优先于跨 provider 备用**（先换账号，再换模型）

> **aiworkgate 缺的是第 1 条**：有重试但没有「已开始回复后就锁定」的显式边界。

### 2.5 亲和（`affinity.go` 1402 行）

实测 trace 里的字段：
```json
"affinity":{"mode":"","turn":1,"last":"loomy","lastTurn":1,"at":"...","cacheWrite":21,"why":"no-cache"}
```

`why` 的取值能解释「为什么没粘住」：`first`（首轮）/`no-cache`（缓存已失效）等。
**aiworkgate 的 sticky 没有 `why`**，出问题时无法诊断。

文件很短，说明实现很干净——对应截图里的 `openrouter/*:free` 与 `re:...`。

## 9 · 不可沿用的部分（避免误导）

| magpie 特性 | 为什么不要 |
|---|---|
| 托盘/Dock/菜单栏（Wails 桌面） | aiworkgate 是 Web + tray，架构不同 |
| TUI / claudeTUI | 你不需要终端界面 |
| `noBird`（加载动画的鸟） | 纯装饰 |
| PanelShortcut / SessionTerminal | 桌面专属 |
| `pii` 模型层（ONNX 390 文件） | 成本高；先做规则层，模型层后置 |
| Codex/Claude 会话读取（`sessions`） | 你的产品形态不同，除非要做"读取其他 agent 历史" |
